## 0. 调整结论

产品的核心内容层级调整为：

```text
一次创作会话（Conversation）
  └── 一个作品集（StoryCollection）
        ├── 作品 1（StoryWork）
        ├── 作品 2（StoryWork）
        └── 作品 N（StoryWork）
```

- **创作首页**负责围绕当前会话持续创作，并原位呈现该作品集内的全部作品、播放状态和续播生成进度。
- **故事库**以作品集为第一层展示单位，不再把同一会话中的每条作品平铺成互不相关的记录。
- **作品**仍是可独立播放、保存正文、记录播放进度和拥有音频资产的最小内容单位。
- **作品集**是用户理解、命名、回访和在播放器中识别内容的主要单位。
- **播放**继续是跨页面的 Global Now Playing，不恢复独立播放器一级页面。
- **提示词历史 / 生成历史**不再作为产品概念或兼容数据保留；作品集成为唯一的创作历史资产入口。
- **连续创作**在新建创作时默认开启，并继承设置页配置的默认播放时长；系统自动创作并播放下一条作品，直到本次播放预算耗尽或用户主动中止。

一句话心智：

> 用户在一次会话里创作一个作品集；作品集由多条可播放作品组成，故事库收藏作品集，播放器始终告诉用户正在听哪个作品集中的哪条作品。

## 1. 术语与对象边界

| 产品概念 | 定义 | 用户可见身份 | 生命周期 |
| --- | --- | --- | --- |
| 创作会话 `Conversation` | 一次连续对话与创作上下文 | 不单独作为资产展示 | 用户新建会话时开始，可继续进入 |
| 作品集 `StoryCollection` | 与会话一一对应的资产容器 | AI 生成的作品集标题 | 随会话首个有效作品创建，长期保留 |
| 作品 `StoryWork` | 会话中一次完成的故事内容 | 集内序号、可选短标题/摘要 | 每次有效故事完成后加入当前作品集 |
| 作品音频 `StoryAudio` | 一条完整作品对应的一条 canonical 音频 | 一首可播放 track | 按需生成，按缓存策略回收 |
| 播放会话 `PlaybackSession` | 当前播放对象与进度 | 作品集标题 + 当前作品信息 | 跨页面连续存在 |

约束：

1. 一个 Conversation 只归属一个 StoryCollection；一个 StoryCollection 也只来源于一个 Conversation。
2. 用户在当前会话中继续创作、续写或生成新故事，结果都追加到同一作品集。
3. 用户显式“新建创作”时，才开启新 Conversation；首个有效作品完成后创建新的 StoryCollection。
4. 仅有闲聊、失败生成或被中断且没有完整作品的会话，不产生空作品集，不污染故事库。
5. 作品集删除、收藏、重命名是集合级行为；单条作品是否允许移除或重排留到后续版本，不在本轮扩大范围。
6. 旧的 Prompt History 与 Generation History 不再与 Conversation / StoryCollection 并存；不得继续形成第二套历史事实源。
7. 一条完整作品 Message / Artifact 对应一个 StoryWork，也对应一条用户可感知且可缓存的 StoryAudio；正文段落不是音频曲目边界。

## 2. 作品集的创建与 AI 标题

### 2.1 创建时机

为避免空资产和失败资产，产品文案中的“会话创建作品集”落到系统行为时定义为：

> 新会话的第一条完整作品生成成功后，原子创建作品集并把该作品作为第一个成员写入。

后续作品生成成功后直接追加到该作品集。若作品保存暂时失败，创作卡保留正文和重试能力，但故事库不提前显示半成品集合。

### 2.2 标题生成

作品集创建时由 AI 根据首轮创作意图与首个完整作品生成一个简洁标题：

- 标题表达整组内容的共同主题，而不是机械复制用户提示词；
- 建议展示长度为 4～18 个中文字符，存储上限沿用 80 个 Unicode code points；
- 标题只在创建时自动生成一次，后续追加作品不自动改名，避免故事库与播放器中的身份漂移；
- 用户后续可以手动重命名；手动标题永远优先，不再被 AI 覆盖；
- AI 标题生成失败或超时不能阻断作品入库，使用确定性回退：正文严格标题 → 提示词摘要 → `未命名作品集`；
- 重试创建必须保持幂等，不能因标题请求重试生成多个作品集。

### 2.3 展示规则

- 故事库卡片主标题：作品集标题。
- Expanded / Mini Now Playing 主标题：作品集标题。
- 播放器副标题：当前作品在集内的位置和短摘要，例如“第 2 个故事 · 月球上的小狐狸”。
- 创作卡片不重复铺满作品集标题；页面上下文固定展示当前作品集标题，卡片只表达当前作品身份与状态。

## 3. 页面信息架构

### 3.1 创作首页

根路由与 `/chat` 仍是创作空间。一次会话对应一个作品集，页面建议分为：

```text
创作页
├── 当前作品集头部
│   ├── AI 作品集标题（首作完成前显示“新作品集”）
│   └── 作品数量 / 总体状态
├── 对话与作品流
│   ├── 用户消息
│   ├── 作品卡 1（可播放）
│   ├── 续播生成卡 / 预加载卡
│   └── 作品卡 N（可播放）
└── 创作输入
```

创作页中的每条完整作品卡都提供原位播放能力。点击播放后不跳转故事库；Global Now Playing 同步接管跨页面控制。

创作页持续展示“连续创作已开启”和本次剩余播放时长。每次新建创作默认开启该能力，并读取设置页当时配置的默认播放时长作为本次预算；用户可以在首条作品播放前或运行过程中关闭。

移除每条作品卡上的以下旧入口与文案：

- “已保存到作品库”；
- “查看作品”；
- 每条卡片单独跳转 `/library/:workId` 的主 CTA。

保存失败仍需在对应卡片上明确显示并允许重试，因为这是恢复资产一致性的操作，不是作品库导航入口。

创作页不再展示“提示词历史”或“生成历史”入口、面板、快捷恢复项。用户回访过去的创作统一从故事库选择作品集；用户继续当前创作统一在当前会话完成。

### 3.2 “清除”调整为“新建创作”

聊天框当前的“清除”容易被理解为删除消息、删除作品、清空输入，或清除播放状态。新模型下该动作改为明确的：

> **新建创作**：结束当前创作上下文，开启一个空的新 Conversation；待首个完整作品完成后形成新的 StoryCollection。

交互规则：

- 按钮名称使用“新建创作”，不再使用“清除”“清空”或垃圾桶图标作为主语义；建议使用新建/加号类图标。
- 该动作不删除当前作品集、不删除已完成作品，也不清除故事库资产；当前作品集仍可从故事库回访。
- 若当前会话有已发送消息、正在生成的内容、尚未保存的完整 Artifact 或输入框草稿，点击后必须出现确认提示。
- 确认提示使用结果导向文案，例如：“开始新的创作？当前作品集会保留在故事库，未发送的输入不会保留。”
- 若存在正在生成或正在准备的下一条作品，确认新建后取消其前台任务并使用 epoch/session guard 屏蔽迟到响应，不能把结果写进新作品集。
- 若存在保存失败但正文完整的 Artifact，确认提示必须额外说明尚有作品未成功保存；默认不静默丢弃。
- 若页面是完全空白的新会话且没有草稿，再次点击“新建创作”不创建多余会话、不创建空作品集，可保持当前空态。
- 确认新建后必须中断并清除当前创作页关联的全部运行态：正文生成、作品晋升/保存、AI 续播、TTS 请求、音频预加载、播放队列、播放进度镜像和错误/重试状态。
- 正在播放或暂停的当前作品必须立即停声并卸载当前媒体；Global Now Playing 回到无曲目的初始 idle 状态，不保留旧作品的暂停/继续播放入口。
- 所有旧任务的迟到响应必须被 session/epoch/token guard 丢弃，不能恢复旧卡片、重新起播、污染新会话或写入新作品集。
- 页面在同一原子重置结果中回到初始创作态：空对话流、空输入框、“新作品集”占位、无续播卡、无播放卡高亮。
- 新会话建立后，页面头部显示“新作品集”；首作完成并成功建集后替换为 AI 生成标题。

“删除作品集”仍只在故事库的集合级生命周期操作中出现，与“新建创作”严格分离。

### 3.3 故事库

故事库列表的第一层实体由 StoryWork 调整为 StoryCollection：

- 一张卡代表一个作品集；
- 卡片显示 AI/用户标题、作品数量、最近更新时间、总播放进度、收藏与删除操作；
- 点击卡片进入 `/library/[collectionId]`；
- 搜索默认覆盖作品集标题，并可匹配集内作品正文/摘要，但结果仍按作品集聚合展示；
- 收藏、回收站、恢复和永久删除默认作用于整个作品集。

作品集详情展示集内作品列表。每条作品均可独立播放，并显示自己的就绪、拉取、播放、暂停、失败和进度状态。

#### Mini Player 底部安全区

故事库列表必须根据底部 UI 的实际组合动态保留滚动安全距离：

- 无 Mini Player 时，列表底部至少避让 Bottom TabBar 与设备 `safe-area-inset-bottom`；
- Mini Player 出现时，底部安全距离必须再增加 Mini Player 的实际占用高度及组件间距；
- 最后一张作品集卡的正文、进度和操作区必须能够完整滚动到 Mini Player 上方，不能被遮挡或只能露出一部分；
- 加载更多指示器、空结果尾部、Toast/Undo 操作条也必须落在可见安全区内；
- Mini Player 展开、收起、尺寸变化或响应式断点切换时，安全距离同步更新，不保留错误的固定空白；
- 不通过给最后一张卡写死 margin 修补，应由页面滚动容器消费共享的 Now Playing / TabBar 占位变量。

### 3.4 Global Now Playing

Global Now Playing 继续是单一播放控制面，显示层级统一为：

```text
作品集标题
当前作品（序号 / 短标题）
当前作品的统一时间进度
```

从创作页或作品集详情播放任意作品时，都切换到同一个播放会话；跨 Tab 导航不停止音频，也不丢失当前作品与集合身份。

## 4. 提示词历史与生成历史退役

### 4.1 产品裁决

Prompt History 与 Generation History 是旧的过渡模型：前者保存可再次发送的提示词，后者以单条生成结果模拟资产。在“一次会话对应一个作品集”后，两者都与正式会话和作品资产重复，且会制造多个不一致入口，因此本轮采用物理退役，而不是隐藏 UI。

目标状态：

- 创作页、故事库、播放器和设置中均无“提示词历史 / 生成历史”入口、Tab、卡片或文案；
- 不再记录、同步、恢复、裁剪或迁移新的 Prompt History / Generation History；
- 不再通过点击历史提示词自动发送、重建 Draft Session 或触发故事生成；
- 不再保留以 prompt 或旧 generation record 作为 playback source 的正式路径；
- Conversation、StoryCollection、StoryWork 成为创作上下文与资产的唯一事实源。

### 4.2 数据与代码退役范围

实施时必须清理完整纵切面，不能只删除页面入口：

1. 删除 Prompt History / Generation History 的客户端 store、持久化 key、初始化与身份切换编排。
2. 删除相关服务、API/router、schema、兼容 adapter、数据同步、30 天裁剪和自动发送桥接。
3. 删除历史面板、列表、入口、样式、埋点与专属测试 fixture。
4. 删除把 legacy generation record 解析为播放源或 Draft Session 的兼容路径。
5. 数据库旧表/字段采用单独 migration 方案安全退役；先证明有效内容已属于 StoryCollection/StoryWork，再删除结构，不允许误删当前作品资产。
6. 清理浏览器 localStorage / IndexedDB 中的旧 history key；清理必须幂等、主体安全，且不得误清当前 Conversation、作品集或播放进度。
7. 更新 README、e2e、Catalog 与代码静态守卫，防止旧命名和入口回流。

### 4.3 旧数据处理原则

- 已经晋升为 StoryWork 的内容以正式作品资产为准，不因 history 退役而删除。
- 只有 Prompt History 中存在、从未形成作品的提示词不迁移；它不是用户作品资产。
- 只有 Generation History 中存在且尚未对应 StoryWork 的旧记录，需在实施前盘点；若生产确有此类有效内容，先进行一次性幂等 backfill，再删除旧数据结构。
- 迁移、删除数据库结构及生产数据不属于本文档阶段，必须另写可回滚计划并获得明确发布授权。

## 5. 创作页作品卡的播放与拉取状态

每条可播放作品卡必须由共享播放状态派生出明确 UI，不能建立与 Global Now Playing 分叉的本地播放器状态。

| 卡片状态 | 用户可见反馈 | 主要操作 |
| --- | --- | --- |
| `ready` | 播放图标；有断点时显示“继续播放”与进度 | 播放 / 继续播放 |
| `fetching_audio` | 按钮进入 loading；文案“正在准备语音…” | 可取消切换，不可重复发起 |
| `playing` | 卡片高亮、动态声波或等价动效，显示“正在播放” | 暂停 |
| `paused` | 保留当前进度与明确暂停态 | 继续播放 |
| `failed` | 文案“语音准备失败”，不暴露底层错误 | 重试 |
| `expired` | 文案“语音缓存已过期，将重新准备” | 重新播放并生成缓存 |

并发与一致性约束：

1. 任一时刻只能有一条作品是 `playing`。
2. 拉取 A 的音频时用户改点 B，A 的迟到响应不得抢占 B；A 已生成的合法缓存可保留。
3. 卡片、Mini、Expanded 必须消费同一个 `workId + playbackSessionId` 状态源；不得把内部合成 chunk/segment identity 暴露为产品播放身份。
4. `fetching_audio` 与故事正文仍在生成必须是两种不同视觉语义。
5. 卡片滚出视口后，Mini/Expanded 仍能完整表达当前播放状态。

## 6. 续播生成与预加载卡

现有预加载不能只在后台发生。只要系统为了连续收听而开始生成下一条内容，创作流中就应立即出现一张与最终作品占据同一位置的状态卡。

### 6.1 状态机

```text
queued → generating_text → preparing_audio → ready
   └───────────────→ failed ←──────────────┘
```

- `queued`：已进入续播队列，显示“即将续写下一篇”。
- `generating_text`：流式展示正在生成的正文，并显示“正在续写”。
- `preparing_audio`：正文已完成，显示“正在准备语音”。
- `ready`：原地转为正式作品卡，加入当前作品集并可播放。
- `failed`：保留已生成正文（如有），显示失败原因的用户化文案与重试操作。

### 6.2 进度表达

- 不展示无法兑现的虚假百分比；用阶段文案、流式正文和确定性步骤表达进度。
- 若后端能够提供分段总数，可显示“正在准备语音 1/3”；不能提供时使用不定进度动效。
- 预加载卡必须与触发它的当前作品存在视觉连续性，但不能嵌套在播放器组件内部。
- 用户暂停播放后，遵循既有成本约束，不继续发起新的投机性 TTS；已完成的正文与合法资产不丢弃。
- 用户可继续正常输入，新输入不应被后台续播卡覆盖或清空。

### 6.3 作品边界

本文把“每条作品”定义为创作流中一次完整交付的故事 Artifact。后台续播若产出新的完整 Artifact，它就是当前作品集中的下一条作品；同一作品内部的语音合成批次只更新该作品卡的音频准备状态，不创建新作品，也不形成用户可见的段落播放状态。

### 6.4 当前预加载与续播逻辑确认

截至本文提出时，代码中实际存在两套名称相近但含义不同的预加载：

**A. 同一条作品内部的下一音频段预取（当前正式主路径）**

1. 一条故事 Message 先被 `segmentStoryText()` 拆成多个 paragraph/segment。
2. 当前段实际播放时，进入距结尾约 5～10 秒的自适应窗口
   `min(10, max(5, duration * 25%))`，预取紧邻的下一段，严格 `lookahead = 1`。
3. 只有 Transport 正在播放时才触发；暂停、离线、已经在预取，或分钟定时预算耗尽时不发起新的预取。
4. 当前段 `ended` 后自动推进 `nextParagraphIndex` 并播放下一段；直到该 Message 的全部段落结束。
5. Work 且 canonical audio flag 开启时走 `ensureSegment(workId, segmentIndex, sessionId)`；Draft 或 flag 关闭时直接按该段文本调用 TTS。

**B. 播放到故事末尾后 AI 自动生成下一条故事（当前兼容路径，不是稳定正式行为）**

1. 只有 Playback Session 的 `continuationMode === 'extendable'` 才允许在尾段进入 AI continuation；默认 `finite` 会在当前作品全部段落播完后停止。
2. 当前正常入口——创作卡播放、作品回放、生成完成后自动起播——都通过正式 Session 创建，且没有显式设置 `extendable`，实际默认是 `finite`。
3. 自动续写兼容链调用固定提示词“请继续故事”，通过 `beginChatStream(..., origin: 'preload')` 生成新的 assistant 故事 Message 和临时音频；隐藏内部提示词，不清空用户输入草稿。
4. 若在接近结尾时已生成完成，当前音频结束后消费该结果；没有结果时旧链可能现场请求。失败按 5 秒间隔重试，最多 3 次。
5. 该兼容链主要为无正式 Session 的 legacy audio 或显式 `extendable` 尾段保留；从当前正式入口看，不能把它视为用户现已稳定获得的“自动生成下一作品”功能。

因此当前真实结论是：

> 现在稳定工作的“续播”主要是同一条 Message 内多个音频段的自动衔接；作品与作品之间的 AI 自动续写默认没有开启。

这也说明本文前述“续播生成卡”不能直接按现有代码宣称已经存在。新的集合模型采用方案 B：

> 每次新建创作默认开启“连续创作”，并继承设置页配置的默认播放时长。系统在当前作品接近结束时自动生成下一条作品，并连续创作、连续播放至本次预算耗尽；用户关闭后，当前作品播完即停止。

无论选择哪一项，新模型都不再使用“下一 paragraph 音频预取”向用户表达续播。单条作品音频应作为一个 StoryAudio 准备；“续播”一词只用于作品集内从当前作品走向下一条作品。

### 6.5 连续创作产品契约（方案 B，已确认）

#### 默认开启与预算继承

- 入口只放在创作页的当前作品集上下文中，不作为故事库回放的默认行为。
- 每次新建创作时默认设置 `continuousCreation = enabled`，无需额外确认弹窗；创作页必须直接、持续显示开启状态，避免隐性消耗。
- 本次预算读取设置页在新建创作当时配置的默认播放时长，并形成该 Conversation 的预算快照；运行期间修改设置页默认值不追溯改变已开始的本次预算，下一次新建创作再读取新值。
- 预算沿用 Playback Session 的睡眠定时语义，以实际有效播放时间扣减，不把正文生成、语音准备、缓冲或暂停时间计入播放预算。
- 用户可以在首条作品播放前调整本次预算或关闭连续创作；调整只影响当前 Conversation，不反向修改设置页的持久化默认值。
- 用户关闭后，本次 Conversation 保持关闭；再次手动开启时沿用当时剩余预算，而不是重置为完整默认时长。
- 若当前没有可播放作品，先按正常创作流程完成首条作品；首条作品开始实际播放后才开始扣减预算。

#### 自动生成与衔接

1. 当前作品进入接近结束窗口且连续创作已开启、预算仍有效、页面会话仍匹配时，创建下一条作品的可见状态卡。
2. 状态卡依次表达 `queued → generating_text → preparing_audio → ready / failed`，生成结果追加到当前作品集。
3. 当前作品播完时：下一条 StoryAudio 已 ready 则自动播放；仍在准备则播放器进入明确的“等待下一篇”状态，准备完成后在同一已授权连续会话内自动起播。
4. 任一时刻最多生成一条下一作品，严格 `work lookahead = 1`；不得并行投机生成第 N+2 条。
5. 自动续作必须继承当前 Conversation 上下文和作品集主题，但每次产出新的 Message / Artifact / StoryWork / StoryAudio，不把正文拼进上一条作品。

#### 停止条件

出现以下任一条件后，不再调度下一条作品：

- 播放预算耗尽；
- 用户关闭“连续创作”；
- 用户暂停播放；恢复播放后是否继续自动创作，以本次开关仍开启且预算有效为准，但暂停期间绝不新发生成或 TTS；
- 用户点击“新建创作”；
- 用户切换播放到其他作品集或从故事库主动播放另一作品；
- 当前作品、作品集或主体失效；
- 连续生成失败且重试达到上限。

预算耗尽时必须立即停声、取消尚未开始的下一条任务，并将连续创作状态置为结束。已经完整生成并成功入库的作品保留；正在生成但未完成的 Artifact 按中断态保留在当前会话，不晋升为正式作品。

#### 用户控制与可见性

- 创作页持续显示“连续创作已开启”及剩余播放预算，不能只在设置页或播放器深层展示。
- 用户可以随时关闭；关闭只阻止后续创作，不删除已完成作品。
- 正在自动生成下一条时，卡片提供“停止连续创作”；停止后取消在途任务并屏蔽迟到响应。
- 用户手动输入新要求时，以用户输入为更高优先级：取消尚未完成的自动续作，将用户请求作为当前作品集的下一次创作。
- 离开创作页不隐藏能力状态；若允许跨页面继续运行，Mini / Expanded 至少显示“连续创作中 / 等待下一篇”及剩余预算，返回创作页可看到对应状态卡。

## 7. 一条作品对应一条音频

### 7.1 现状确认

截至本文提出时，现有实现不是“一条 Message 一条音频”：

- `utils/segmentation.ts` 会先按换行拆分正文；
- 短段按最小阈值合并，超长段按句末标点继续拆分；
- 当前常量为最小合并阈值约 80 字符、目标约 160 字符、最大块约 350 字符；
- Playback Session 以 `paragraphIndex / segmentIndex` 推进，并在接近当前段末尾时预取下一段；
- Canonical Audio 也以多个 `StoryAudioSegment` 作为持久化与播放读取单位。

该模型把技术分段升级成了用户可感知的播放边界，会导致一条作品出现多次准备、切换和进度跳转，与“一条回复就是一条作品音频”的认知不一致，因此需要调整。

### 7.2 产品裁决

目标契约是：

> **一条完整的作品 Message / Artifact = 一个 StoryWork = 一条 StoryAudio = 播放器中的一首 track。**

具体规则：

- 一条作品只有一个播放按钮、一个总时长、一条连续时间轴、一个缓存状态和一个播放完成状态。
- 播放从该作品音频的开头或统一时间进度继续，不显示“第 N 段”、段落切换或多个音频加载周期。
- 播放完成的边界是整条作品音频结束；完成后才允许切换到作品集中的下一条作品或触发新的续播创作。
- 30 天缓存以整条 StoryAudio 为单位命中、刷新与过期，不能出现同一作品部分段落已缓存、部分段落向用户显示重新准备的割裂状态。
- 作品正文可以保留自然段用于阅读，但正文排版段落与音频资产边界彻底解耦。

### 7.3 技术实现自由与硬边界

考虑 TTS Provider 的单次文本长度、超时和合成稳定性，底层允许把长正文拆成内部 synthesis chunks，但这些 chunk 只能是实现细节：

1. 服务端完成分批合成后，必须拼接、封装或通过等价的连续媒体机制，对客户端交付一个 canonical StoryAudio 身份。
2. 各 chunk 的断句不能截断词语、句子或制造明显的声学停顿；拼接后音量、采样格式和音色一致。
3. 客户端播放、缓存、授权 URL、进度、重播和失败恢复均以 StoryAudio / workId 为边界，而不是 segmentIndex。
4. 内部单个 chunk 失败时，产品上仍是该作品“语音准备失败”；可做断点重试，但不能让用户逐段修复或逐段播放。
5. 不得为了降低首播等待重新把内部 chunk 暴露成多首音频。若未来需要边生成边播放，应提供同一 track 下的连续流式音频和稳定时间轴。

### 7.4 与断点续播的关系

现有“段落边界续播”属于旧技术模型，需要在实施方案中重新设计：

- 产品目标是作品级单 track 续播，优先恢复统一时间轴上的合理进度；
- 若首版受存储或浏览器能力限制不能可靠恢复秒级进度，可以从作品开头重播，但不得继续向用户呈现多段 track；
- 最终续播精度、进度落库频率和跨设备语义需在新的 Playback 设计中单独裁决，不能直接沿用 `nextParagraphIndex` 作为新模型事实源。

## 8. 音频缓存 30 天

### 8.1 产品规则

每条作品都可播放，但“可播放”不等于音频文件永久保存：

- 正文、作品元数据、作品集关系和播放进度按资产规则长期保留；
- 已物化的整条 StoryAudio 采用 **30 天滑动缓存**；
- 30 天从该作品音频最近一次成功访问时间计算；命中播放会刷新访问时间；
- 到期回收只删除可再生的音频二进制及其可用投影，不删除作品正文、集合关系或播放进度；
- 用户再次播放过期作品时，按正文和原语音配置重新生成，从卡片进入 `fetching_audio`，成功后继续播放；
- 正在播放、正在拉取、持有有效生成 lease 的作品音频不得被 GC；
- 音色或分段算法版本变化产生新的资产身份，旧版本按各自最近访问时间独立回收；
- 访客主体的全部数据仍受既有 30 天 Guest GC 约束；访客身份过期时不因音频缓存而延长主体生命周期。

### 8.2 用户感知

通常不向用户展示具体缓存倒计时。只有命中已缓存音频时快速播放；缓存缺失或过期时明确显示“正在准备语音”。若重新生成失败，作品正文仍可阅读，且提供重试。

### 8.3 非目标

- 本轮不承诺 PWA 离线播放或设备本地永久下载。
- 本轮不一次性预生成整套作品集音频；按用户即将播放的当前作品懒物化完整 StoryAudio，不再采用用户可见的段落 `lookahead = 1` 播放模型。
- 本轮不把缓存 TTL 混同于作品或回收站的保留期。

## 9. 关键用户旅程

### 9.1 首次创作

1. 用户进入创作页，看到“新作品集”。
2. 用户提出创作要求，AI 生成第一条完整作品。
3. 系统创建作品集、生成标题并保存首条作品；标题失败时使用确定性回退，不阻断保存。
4. 第一条作品卡原位可播放；点击后卡片显示音频准备，再进入播放态。
5. Mini / Expanded 显示作品集标题和“第 1 个故事”。

### 9.2 同会话继续创作

1. 用户继续输入新要求，或播放链触发续播生成。
2. 新的状态卡在对话流中出现并持续表达生成进度。
3. 完成后状态卡原地成为第 2 条作品，归入同一作品集。
4. 故事库仍只新增/更新一张作品集卡，而不是新增第二条顶层记录。

### 9.3 从故事库回访

1. 用户在故事库看到作品集标题与“共 N 条作品”。
2. 进入作品集详情，选择任意作品播放。
3. 若缓存有效，直接进入播放；若缓存缺失/过期，所选条目显示正在准备语音。
4. 用户返回创作或切换页面，Global Now Playing 持续播放并保持集合与作品身份。

### 9.4 新建创作

1. 用户在已有作品的会话中点击“新建创作”。
2. 产品说明当前作品集会保留，并对草稿、在途生成或未保存作品给出准确风险提示。
3. 用户确认后，当前正文生成、续播、保存、TTS、音频预加载和播放全部中断；页面与 Global Now Playing 恢复初始 idle 状态。
4. 用户进入空的新会话；旧作品集仍在故事库，但不保留旧会话的播放或页面运行态。
5. 旧会话迟到的生成、保存或音频响应不得进入新会话，也不得重新起播。
6. 新会话首作完成后建立另一个具有 AI 标题的作品集。

### 9.5 连续创作至预算耗尽

1. 用户新建创作后，页面默认显示“连续创作已开启”，本次预算取自设置页配置的默认播放时长。
2. 当前作品实际播放后开始扣减预算；进入结尾窗口时出现下一作品状态卡。
3. 下一作品完成后加入同一作品集，并在当前作品结束后自动衔接播放。
4. 系统始终只提前准备一条下一作品，循环执行直到剩余预算耗尽。
5. 预算耗尽时立即停止播放和后续调度，页面明确显示“本次连续创作已结束”；已完成作品全部保留。

## 10. 验收口径

后续进入实施时，至少把以下行为写入 `docs/e2e` 并登记 Catalog：

1. 同一 Conversation 连续生成三条完整作品，故事库只出现一个 StoryCollection，详情包含三条有稳定顺序的 StoryWork。
2. 新建 Conversation 后生成作品，创建另一个 StoryCollection；两个会话的作品绝不串集。
3. 首作成功时 AI 标题生成并持久化；标题服务失败使用回退且不阻断入库；重试不重复建集。
4. 故事库与 Mini / Expanded 使用同一作品集标题；用户改名后各处一致更新。
5. 创作页不再为每条作品显示作品库入口；每条完整作品都能原位播放。
6. 正在拉取音频和正在播放的作品卡具有明确且互斥的视觉状态，迟到响应不能抢播。
7. 续播生成开始后立即出现状态卡，完整经历生成正文、准备语音、就绪或失败，不产生不可见后台进度。
8. 音频 30 天内命中不重复 TTS；超过 TTL 后正文仍在，再次播放触发重生成；GC 不删除正在使用的音频。
9. 创作卡、作品集详情、Mini 与 Expanded 的播放源、段落和进度保持同源。
10. 集合收藏、软删除、恢复与永久删除不留下可访问的孤儿作品或音频。
11. 全产品不再显示或写入 Prompt History / Generation History；旧 API、store、缓存 key 和兼容播放源均有静态与行为守卫。
12. “新建创作”不删除旧作品集；有草稿、在途生成或未保存作品时必须确认，并原子中断生成、保存、续播、TTS、预加载与播放，页面和 Global Now Playing 恢复初始态，旧响应不能污染新会话或重新起播。
13. 空白无草稿会话重复点击“新建创作”不产生空集合或冗余会话记录。
14. 任意一条完整作品无论正文包含多少自然段，前端只呈现一条音频、一个总时长和一条连续时间轴；播放过程无可感知的 paragraph/segment 切换。
15. 长文本即使底层分批 TTS，最终也以一个 canonical StoryAudio 缓存和授权；内部 chunk 失败或重试不产生多条作品音频。
16. 整条 StoryAudio 播完才算作品完成；不得在内部 chunk 结束时误触下一作品或 AI 续播。
17. 故事库出现 Mini Player 时，最后一张作品集卡、加载更多与 Undo 操作条均可完整滚动到播放器上方；Mini 消失后不残留多余固定空白。
18. 每次新建创作默认开启连续创作，并准确继承设置页当时的默认播放时长；创作页持续显示开启状态与剩余预算，用户可随时关闭。
19. 连续创作严格只准备下一条作品；播放预算只按有效出声时间扣减，暂停、生成、TTS 与缓冲不扣减。
20. 预算耗尽、关闭连续创作、新建创作或切换作品集后不再产生下一作品，所有迟到响应不得起播或入错集合。

## 11. 对现有方案的影响

| 现有模块 | 需要修订的旧假设 | 新方向 |
| --- | --- | --- |
| M2 StoryWork | StoryWork 是故事库顶层资产；无 `sourceConversationId` | 引入稳定 Conversation / StoryCollection identity，StoryWork 从属于集合 |
| M3 Library | 列表、搜索、收藏、删除以 StoryWork 为单位 | 顶层切换为 StoryCollection，详情管理集内 StoryWork |
| M4 Chat Artifact | Modern Artifact 无播放；ready 后“查看作品” | 完整 Artifact 卡原位可播放；移除逐条作品库入口 |
| M5 Playback | Work 内以 paragraph/segment 推进并持久化段落边界 | 播放源仍是 Work，但一条 Work 只有一条用户可感知 track；续播模型需重做 |
| M6 / M7 Now Playing | 主标题可直接使用 Work title | 主标题统一为 Collection title，副标题表达当前 Work |
| M8 Canonical Audio | 一个 Manifest 下持久化多个可独立读取的 AudioSegment | 对客户端收敛为一个 canonical StoryAudio，并增加整条音频 30 天滑动回收契约 |
| Legacy History | Prompt / Generation History 仍有 store、API、同步与兼容恢复职责 | 产品、数据与代码完整退役，以 Conversation / Collection / Work 为唯一事实源 |
| Chat reset | “清除”可能同时暗示删消息、删资产或清输入 | 改为“新建创作”；历史资产保留，但当前创作、预加载与播放运行态全部中断并归零 |
| Library layout | 列表底部只考虑 TabBar，Mini 出现时可能遮挡尾部内容 | 滚动容器动态消费 Mini + TabBar + safe area 的共享占位 |
| Continuation | 正式 Session 默认 finite，AI continuation 仅残留在 legacy / extendable 兼容链 | 新建创作默认开启连续创作并继承设置页时长，work lookahead=1，按有效播放预算持续至耗尽 |

## 12. 非目标与待后续设计

本轮产品调整不直接决定：

- 集内拖拽排序、批量移动或把作品跨集合迁移；
- 一个会话创建多个作品集或多个会话合并为一个作品集；
- 协作、分享、公开发布；
- 离线下载和永久音频收藏；
- 单条作品的复杂版本树；
- 旧 StoryWork 数据迁移时如何聚合集合（需单独 migration/backfill 方案）。
