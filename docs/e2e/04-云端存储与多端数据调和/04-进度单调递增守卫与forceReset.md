# 进度单调递增守卫与 forceReset

功能域：04-云端存储与多端数据调和

## 用户目标

用户在同一账号的两个会话（或两台设备）同时听同一故事时，播放进度不被迟到的旧回执倒拉：已听到第 3 段，就不会因为另一端晚到的"第 1 段"回执而跳回去；只有用户主动选择"从头播"时，进度才允许归零重来。

服务端对进度保存按三步处理：先比较新上报的段落序号与已保存的序号，上报更旧时直接返回既有进度而不落库；仅当调用声明从头播（forceReset）时放行归零；其余情况正常落库推进。

## 前置条件

- 服务端预置一条播放进度：已听到第 3 段（`nextParagraphIndex=3`）。
- 通过服务端直接调用进度保存接口。

## 操作步骤

1. 不带 `forceReset` 保存"听到第 1 段"（比当前进度更旧的值），观察返回与落库值。
2. 带 `forceReset=true` 保存"从第 0 段开始"，观察返回与落库值。
3. 不带 `forceReset` 再保存"听到第 1 段"，观察是否正常推进。
4. 双端次序变体：A 端较高的段落回执尚在途中时，B 端先触发从头播，随后 A 端的回执到达，观察最终进度。

## 验收标准

- 步骤 1：旧值被拒绝，返回既有进度，不落库；剩余可听时长与来源标识不受污染。
- 步骤 2：从头播例外放行，进度归零。
- 步骤 3：从 0 起可正常推进。
- 步骤 4：从头播之后到达的迟到旧回执同样被拒绝，不倒拉新进度。

## 边界与异常

- 该守卫是服务端语义，与界面无关：各端看到的进度都以服务端落库值为准。
- 主动"从头播"是唯一的例外放行路径。
