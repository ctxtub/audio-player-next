# 创作、作品集与播放产品决策

本文归档已经实施且仍有解释价值的产品决策。它用于说明产品边界，不作为实施计划或进度记录。

## 内容模型

- 一次创作会话对应一个作品集，首条完整作品成功后创建作品集。
- 一条完整作品消息对应一个作品，也对应一条用户可感知的完整音频；内部可以分块合成，但不得把分块暴露成多条曲目。
- 作品集标题在创建时由 AI 生成，失败时使用确定性回退；用户改名后不得被自动覆盖。
- 故事库以作品集为首层实体，作品集详情展示并播放集内作品。
- 提示词历史和生成历史已经退役；会话、作品集和作品是唯一事实源。

## 创作体验

- 创作页原位显示每条完整作品的准备、播放、暂停、失败和进度状态。
- “清除”使用“新建创作”语义：保留已完成作品集，同时终止当前生成、保存、音频准备、预加载和播放状态，页面回到空白初始态。
- 迟到的异步响应必须通过会话身份与运行代次守卫丢弃，不能污染新会话。
- 连续创作默认开启，启动时继承设置页默认播放时长，并持续创作和播放到预算耗尽或用户主动停止。
- 下一条作品尚未就绪时，页面明确展示等待状态；等待和缓冲不扣播放预算。

## 播放与缓存

- 播放以作品为曲目身份，使用作品集标题作为主要上下文，并由全局播放器跨页面承接。
- 每条作品发布一个完整音频资产，按作品记录秒级播放进度。
- 音频采用三十天滑动缓存；缓存过期后保留作品和进度，再次播放时重新生成。
- 新建创作必须立即停声、卸载媒体并清空全局播放器，不能保留旧作品的继续播放入口。
- 故事库滚动区域必须消费底部导航、迷你播放器和设备安全区的实际占位，最后一张卡片不得被遮挡。

## 数据与兼容边界

- 用户和访客数据保持物理隔离，所有写入验证主体归属。
- 作品晋升是完整作品进入作品集的唯一写入路径，并以来源消息保持幂等。
- 旧数据只在有可靠归属证据时合并，不按时间猜测作品集关系。
- 数据库迁移名称属于已应用迁移身份，不因文案整理而重命名；迁移内容和现行代码不再使用阶段代号描述功能。
