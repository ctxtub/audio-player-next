## 用例规格

- 前置条件/夹具：单会话自包含构建（经快速文本生成启动播放，或经 seed 水合进度）；`{{E2E_PORT}}` 服务与 mock 上游正常。
- 步骤：
  1) 在单会话内使 `/player` 进入活跃播放状态（`audio.paused === false`）；
  2) 在 `/player` 执行硬刷新（`agent_browser_reload` 或 CDP `page.reload()`）；
  3) 观察刷新后 UI 渲染与 `<audio>` 元素状态；
  4) 检查 SQLite 数据库中进度与 `audioUrl` 存储字段。
- UI 断言：硬刷新后播放按钮回到不可播态（`isReadyToPlay=false`）或断点就绪态（根据进度落库情况展示断点就绪），**严禁**出现「UI 标记播放中但实际无声」的幽灵态。
- 音频/浏览器断言：刷新后 `<audio>` 元素存在，`audio.paused === true`，音频内存态 `blob:` 播放停止，无残留播放。
- 网络/数据断言：服务端数据库 `GuestPlaybackProgress`/`UserPlaybackProgress` 进度数据完好，但 `audioUrl`（blob）不持久化落库；若刷新后发起恢复，仅按断点文本重新拉取。
- Hoki 弹性重试处理：构建播放或交互过程中若捕获 503 服务过载或 429 限流错误，强制静默退避 60 秒，单用例允许重试至多 3 次，杜绝直接退出导致未决。
- 容错与退出：执行完毕出具完整 `report.md`，文末明晰给出 VERDICT 后以 exit 0 退出。
- 清理：清空浏览器 cookie 与会话。
- 证据要求：`ui-prereload-playing.png`、`ui-after-reload.png`、`audio.json`、`db.txt`、`report.md`。
- 溯源：`stores/playbackStore.ts:346-358`；`components/AudioPlayer/index.tsx`；`lib/server/chatConversation.ts`。
