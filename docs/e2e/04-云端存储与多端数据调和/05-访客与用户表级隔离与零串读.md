## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}` 产生数据（配置/聊天/进度各 ≥1 行）；随后按 E2E-05-01 路径注册 `{{E2E_USER_A}}` 登录。
- 步骤：1) 访客态造数据；2) 注册/登录；3) AUT-API 比对 `Guest*` 与 `User*` 表行；4) 再以 `{{E2E_USER_B}}` 登录读取。
- UI 断言：登录后 UI 显示迁移后的账号数据；`{{E2E_USER_B}}` 下看不到 A 的任何内容。
- 音频/浏览器断言：不适用。
- 网络/数据断言：核心断言——迁移后写路径全部落 `User*` 表（`UserPlaybackProgress`/`ChatMessage`/`UserConfig`），`Guest*` 行仅作为待 GC 遗留；两账号间零共享主键、零串读（progress 以 `subject` user/guest 分表隔离）。
- 清理：删两账号数据；清 cookie。
- 证据要求：`db.txt`（双表行集）、`network.json`。
- 溯源：`lib/server/playbackProgress.ts:71-110`（user/guest 分支 subject 路由）；`lib/trpc/routers/auth.ts:74-76`（迁移三步）；`stores/accountSync.ts:105-121`（`:116-118` 登录跃迁→`resetAccountData`）。
- 备注：迁移数据保真细节（段落索引/parts/createdAt）由 E2E-05-01 覆盖；本例只裁「表级隔离」。
