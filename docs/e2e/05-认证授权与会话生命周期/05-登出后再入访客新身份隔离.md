# E2E-05-05 · 登出后再入访客→新身份旧数据不可见

| 属性 | 设定值 |
| --- | --- |
| 规范 ID | `E2E-05-05` |
| 所属功能套件 | `05-认证授权与会话生命周期` |
| 规范层级 | 单用例规范（Canonical Test Spec） |
| 优先级 | `P2` |
| 自动化类型 | `AUT-BROWSER+AUT-API` |
| 执行调度 | 阶段 5: 认证、会话生命周期与用户资产就绪（全局队列第 38 项） |
| 待验证假设 | ⚠️ H-19 |

## 用例规格

- 前置条件/夹具：延续 E2E-05-04 终态（双 cookie 已清）；记录登出前访客 ID（若有）与 `Guest*` 行数。
- 步骤：1) `/auth` 点「访客进入」；2) 读取新 `guest` cookie 值；3) UI 读取聊天/配置/进度；4) AUT-API 统计 `Guest*` 表。
- UI 断言：新访客为**空白态**（无旧访客聊天/配置/断点就绪徽标）；onboarding 按新身份判定。
- 音频/浏览器断言：浮窗不出现（无进度可恢复）。
- 网络/数据断言：核心断言——新 cookie 为 `guest=<opaque 签名 token>`（验签还原出 `g_` 开头 gid，不以明文 `g_` 存放；响应体不返 `guestId`，见 `2987754`）且与旧值不同（每次 `enterGuestMode` 新 ID）；旧访客行成为孤儿保留（等待 30 天 GC，见 E2E-06-07）；新访客首条写入挂新 ID。
- 清理：清 cookie；删新旧访客行。
- 证据要求：`db.txt`（新旧 guestId 行集分离）、`network.json`。
- 溯源：`lib/trpc/routers/auth.ts:149-168`（`:151` `g_${crypto.randomUUID()}` 每次新 ID）；`lib/server/guestGc.ts:4,20`（孤儿行 30 天回收）。**待验证假设 H-19**：登出→再入访客产生孤儿访客行且新身份完全隔离（旧数据不可复活）。
