# 会话失效后统一登出闭环

功能域：05-认证授权与会话生命周期

## 用户目标

账号在服务端已不存在（被删除或数据回档）时，用户在应用内的下一次操作能干净地回到登录页：不出现"界面像登录着、请求全被拒绝"的半登录幽灵态。

## 前置条件

- 账号 A 处于登录态；随后该账号在服务端被删除（模拟管理员删号或数据回档）。

## 操作步骤

1. 账号被删除后，在应用内触发任意受保护操作（如刷新聊天页）。
2. 观察登出闭环与落点页面。
3. 变体：登录态标识被篡改后刷新页面，观察是否走同样的闭环。

## 验收标准

- 出现会话失效的登出闭环并落到登录页（携带会话过期标记或等价提示）。
- 不出现半登录幽灵态（界面仍显示账号数据但请求全部被拒绝）。
- 失效闭环清空本地账号数据：播放停止、浮窗消失。
- 非登录注册类的请求被拒绝时走统一登出闭环；身份查询接口的失效分支清除过期标识；之后再进受保护页仍被送回登录页。
- 登录态标识被篡改同样触发该闭环。

## 边界与异常

- 登录/注册接口自身的报错不触发该闭环（见《注册登录校验失败提示》）。
- 访客与匿名身份的请求被拒绝不触发该闭环（仅登录账号走闭环）。

## 实现参考

- `lib/trpc/client.ts`（非登录注册类拒绝进入会话守卫）
- `lib/client/sessionGuard.ts`（再入守卫；访客与匿名不触发）
- `lib/trpc/routers/auth.ts`（过期标识清理与失效分支）
- `stores/authStore.ts`（失效后回到登录页并标记过期）
