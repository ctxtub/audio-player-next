## 操作步骤

1. 静态确认三件套删除（L1 oracle P1）：`components/FloatingPlayer/`、`stores/playbackProgressStore.ts`、`lib/client/playbackProgress.ts` 物理不存在；`app/components/lib/stores` 下 `.ts/.tsx` 注释剥离后含 `@/components/FloatingPlayer` / `@/stores/playbackProgressStore` / `@/lib/client/playbackProgress` 的 import 为 0。
2. 静态确认别名删除（L1 oracle P2）：`stores/playbackStore.ts` 无 `export const useFloatingPlayer`；全仓产品代码 `useFloatingPlayer` 计数 0；`ChatLayout` 经 `usePlaybackStore.playAudio(url, id, { explicit: true })` 直调。
3. 静态确认 server 收口（L1 oracle P3）：`lib/trpc/routers/playback.ts` 无 `getProgress / saveProgress / clearProgress` 定义，7 个正式 procedures 全在；`lib/server/playbackProgress.ts` 删除；`PlaybackProgressDTO / SavePlaybackProgressInput` 删除而 `playbackAnchorDTO / playbackSource / workPlaybackProgressDTO / playbackSessionId / savePlaybackCheckpoint` 全在；产品代码 `trpc.playback.getProgress|saveProgress|clearProgress` 引用为 0。
4. 静态确认 AccountSync（L1 oracle P4）：`stores/accountSync.ts` 含 `playbackSession` 参与项且 import `usePlaybackSessionStore`，不含 `playbackProgress` 参与项与 `usePlaybackProgressStore`。
5. 静态确认水合收口（L1 oracle P5/P6）：`stores/playbackSessionStore.ts` 经 `library.get` 精确 resolve Work、不 import `generationHistoryStore`；经 `playbackDraftSnapshot` canonical resolver 取 Draft；`StoryCardPart` resume 位经 `usePlaybackSessionStore`（draft messageId + next），不读旧 DTO；`storyFlow` 不再消费旧 progress store。
6. 行为回归：begin → checkpoint → refresh/hydrate → resume 全链（Draft/Work 两侧保持 M5 原行为），由既有 Session L1/L2 覆盖（contract/rehydrate/checkpoint-guards/lifecycle-promotion/rehydrate-server/runtime-orchestration + anchor-begin/content-identity），本项不新增 L3，只做定向 browser 回归。
7. 定向 browser 回归（既有 spec，不新增 L3）：M5 hydrate/resume（`l3-playback-pause-refresh-resume`）、M6 Mini（`main-chrome-mobile-docked`）、M7 Expanded（`expanded-playback-capabilities` / `expanded-sleep-timer` / `creation-actions`）、M8 canonical（`canonical-work-playback` / `canonical-closure`），chromium+webkit。

## 边界与异常

- 旧 DTO 若仍被正式 M5 response 共用则保留共用类型只删 endpoint——本次审计确认无共用（Anchor 14 字段与旧 DTO 无交集），故 DTO/Input 同删；`playbackSourceTypeSchema` 四值 parser 与 `lib/playback/legacy.ts` 因仍承载 DB canonical reader 兼容而保留，不属"仅服务 legacy procedure"之列。
