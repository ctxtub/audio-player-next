# 硬刷新后播放停止

功能域：01-基础冒烟与页面基线

## 用户目标

正在听故事的用户如果不小心刷新了页面，播放会停下来，但页面不装假：按钮回到不可播或断点就绪的真实状态，绝不出现"看着在播、实际没声"的假象；听过的进度还在，可按断点文本重新拉取。

## 前置条件

- 播放器页已有活跃播放（声音正在放）。
- 服务可用。

## 操作步骤

1. 在 `/player` 确认进入活跃播放状态。
2. 执行硬刷新（重新加载页面）。
3. 观察刷新后播放按钮与音频元素的状态。
4. 核对服务端保存的播放进度与音频字段。

## 验收标准

- 刷新后播放按钮回到不可播态，或按已落库进度展示断点就绪态。
- 严禁出现"界面标记播放中但实际无声"的幽灵态。
- 刷新后音频元素仍在，但处于暂停态，刷新前的内存播放已停止，无残留声音。
- 服务端播放进度数据完好；音频链接（内存地址）不落库。
- 若刷新后发起恢复，只按断点文本重新拉取音频。

## 边界与异常

- 硬刷新必然停止当前声音，这是预期行为；与之相对，客户端路由切换不中断播放，见《三处播放镜像状态一致》。
- 刷新后是否展示"断点就绪"取决于刷新前进度是否已落库：有进度则就绪可续，无进度则为不可播态。
