# 连续创作预算与停止矩阵

功能域：10-会话与作品集连续创作

## 用户目标

连续创作在预算内自动推进；预算耗尽、用户接管、关闭开关、暂停、切换集合、登出或删除集合时，待命中的下一次生成必须被取消，绝不偷偷续播。

## 范围与边界声明

本场景覆盖 T2 的预算扣减口径与停止/抢占矩阵（L1 + L2 + L3）。
**明确排除**：T1 集合 CRUD、T3 单轨资产、T4 Library UI。

## 契约验收标准

### 1. 预算扣减口径（budget accounting）
- 仅 `audioActive === true`（音频实际推进）时递减 `remainingMs`。
- 生成中、TTS 合成中、缓冲（waiting/stalled）与暂停期间 `remainingMs` 不变。
- `remainingMs` 必须非负；归零时归一为 terminal，不以 0 持久化。

### 2. 预算耗尽（ended_budget）
- `remainingMs <= 0` → 状态 `ended_budget`，停止音频并 abort 在途 next job。
- 耗尽后继续创作需用户显式新建创作（预算重新快照）。

### 3. 停止 / 抢占矩阵（stop & preemption matrix）
- 用户手动输入：立即取消未完成自动续作（用户输入优先），不打断用户提交。
- 关闭开关 → `disabled`，abort 在途 next job。
- 暂停 → 不调度、不扣预算；恢复后按窗口重新调度。
- 切换集合 → abort 且以新 collection identity 重新初始化。
- 登出 / 删除集合 → abort，清除 next job 与预算。

### 4. epoch / token stale guard
- 所有异步回调携带 `collectionId + epoch`；不匹配一律 no-op（丢弃结果、清理资源），不得写回状态或播放。
