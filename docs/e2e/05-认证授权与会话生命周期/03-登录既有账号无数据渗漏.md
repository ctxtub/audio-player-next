# 登录既有账号无数据渗漏

功能域：05-认证授权与会话生命周期

## 用户目标

已有账号的用户在访客试用后登录，只看到自己账号的数据：访客试用的内容不混入账号，账号原有数据不丢失。

## 前置条件

- 账号 A 已有账号数据；浏览器同时持有含访客数据的活跃访客身份。
- 访客态停留在聊天页（`/chat`）。

## 操作步骤

1. 以访客态停留在聊天页。
2. 前往登录页（`/auth`）登录账号 A。
3. 读取聊天、配置、历史、进度四处数据，确认归属。
4. 确认访客原数据行未被登录过程迁移或删除。

## 验收标准

- 登录成功后只显示账号 A 的数据；访客期独有内容（如访客草稿消息）不得出现在登录态。
- 登录跃迁先清空本地旧账号状态再重建：浮窗与播放态无旧音频残留。
- 登录不触发迁移（迁移只发生在注册路径）；访客原数据行原样保留。
- 登录后签发登录态标识并保留访客标识（供登出后回到访客）；后续读取以账号主体为准。

## 边界与异常

- 登录态下有效会话会被优先续签；过期会话加残留访客身份的行为见《会话过期后残留访客身份的恢复》。

## 实现参考

- `lib/trpc/routers/auth.ts`（登录只签发登录态标识，无迁移步骤）
- `stores/accountSync.ts`（登录跃迁清空旧账号数据并重同步）
- `middleware.ts`（有效会话优先续签）
