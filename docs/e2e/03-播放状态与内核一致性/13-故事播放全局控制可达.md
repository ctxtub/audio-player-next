# 故事播放全局控制可达

功能域：03-播放状态与内核一致性

## 用户目标

无论是在聊天页点击一张（可能是旧历史恢复出来的）故事卡"播放故事"，还是在"生成历史"里点"回放此故事"，声音真正响起的那一刻，页面右下/底部就必然已经出现全局迷你播放器（MiniNowPlaying），可以随时暂停、恢复、重播、进入详情；不会出现"有声音但没有全局控制"的悬空播放。

## 前置条件

- 访客首次打开站点（隔离环境）。
- 生成历史场景：已完成至少一次真实创作，生成历史落库。
- 故事卡场景：该助手消息被构造成 Legacy `storyCard` 形态（`parts=[{type:'storyCard',storyText,audioUrl}]`），并清空其播放 Anchor（冷态无 Session）；分别覆盖 `audioUrl` 有值与非空串两种形态。

## 操作步骤

1. 故事卡形态 A：刷新聊天页，确认点击前没有迷你播放器（无预置 Session）。
2. 点击该故事卡的"播放故事"。
3. 观察声音是否真实响起，以及同一帧迷你播放器是否可见、状态为播放中。
4. 故事卡形态 B：把同一行重新植入为 `audioUrl:''`，重复步骤 1～3。
5. 生成历史：打开聊天页"历史"→"生成历史"分段，点击"回放此故事"。
6. 观察声音、迷你播放器可见性与播放状态。

## 验收标准

- 起播（`<audio>` `playing`/`currentTime>0`）与迷你播放器可见必须在**同一帧**同时成立；迷你播放器 `data-status="playing"`。
- 迷你播放器显隐只派生自正式 PlaybackSession（`source !== null && status !== 'idle'`），不得由任何第二套显隐状态驱动。
- 故事卡的 Legacy `part.audioUrl` 绝不被当作第 0 段直接播放：实际音源必须是语音合成 provider 产物（`blob:` 或 `data:audio/*`，绝非 legacy URL），Anchor 身份为该 Draft（`sourceKind='draft'`、`sourceId` 为消息 id）。
- 生成历史回放必须建立正式 Work Session：Anchor `sourceKind='work'` 且 `sourceId` 等于该条历史对应的 StoryWork id。
- 不出现"无 Session 却出声"的窗口；不得合成媒体事件取巧。

## 边界与异常

- 同一故事卡在出声中再次点击是正式暂停（见《故事卡连击双发抑制》），不是本场景断言范围。
- 冷态点击前存在 autoplay 残留 Session 时，必须先清 Anchor（否则测的是续播而非新建），本场景前置显式清理。
