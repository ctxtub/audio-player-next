# 流式生成中再次提交互斥

功能域：02-交互并发与竞态防御

## 用户目标

上一条故事还在生成时，用户提交新问题，旧生成被中止，新问题得到完整回答并正常播放，聊天记录不丢失任何一条用户消息。

## 前置条件

- 访客首次打开站点（无既有身份）。
- 当上游大模型响应变慢时（生成需要等待，便于在流式过程中再次提交）。

## 操作步骤

1. 在输入框输入一句话并发送（记为 A），等待流式生成开始。
2. 在 A 还在流式生成时，输入另一句话并发送（记为 B）。
3. 等待生成结束，观察聊天流中 A 与 B 的消息去向。
4. 观察自动播放播的是哪一条故事，B 的卡片内容是否纯净。

## 验收标准

- B 的用户气泡始终保留，不因旧流的中止处理而消失。
- 最终呈现 B 的完整回复；不出现两条发送中消息并存，也没有两条消息同时消失的终态。
- 只有最后完成的故事触发自动播放。
- 旧流的文本不混入 B 的卡片。
- 旧流的生成请求被中止，不再继续写入。
- 保存的会话快照与界面一致，不含被清除的消息。

## 边界与异常

- 旧流被中止后，其未完成的部分回复不可恢复，界面以 B 的完整回复为准。
- 若 B 也失败，失败标记与重试行为见《失败消息重试上下文正确性》。
