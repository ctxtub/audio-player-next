## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}` 造齐四块数据：配置 ≥2 字段、聊天 ≥6 条（含 1 张故事卡带 parts）、进度行（`nextParagraphIndex=2`、`remainingAllowedMs` 数值）、生成/提示词历史各 ≥1 条。
- 步骤：1) `/auth` 注册 `{{E2E_USER_A}}`；2) 注册成功即登录；3) AUT-API 比对 `User*` 表与迁移前 `Guest*` 表行；4) UI 读取四块数据。
- UI 断言：注册后聊天/配置/历史/断点就绪徽标完整呈现迁移内容；无重复条目。
- 音频/浏览器断言：断点就绪可播（进度迁移后 `hydrateFromDTO` 命中源消息）。
- 网络/数据断言：核心断言——三步迁移（用户创建→四块数据复制→访客行保留待 GC）后 `User*` 表内容与访客期一致：段落位置、`parts` JSON、`createdAt`、`nextParagraphIndex` 保真；`Guest*` 原行不删（GC 面见 E2E-06-07）。
- 清理：登出；删 A 账号与访客行。
- 证据要求：`db.txt`（迁移前后 diff）、`ui-after-register.png`。
- 溯源：`lib/trpc/routers/auth.ts:74-76`（注册内三步迁移）；`lib/server/chatConversation.ts:97-106`（`sanitizeParts` 保真语义）；`stores/authStore.ts:82-94`（`:87` 注册成功→登录态）。
