# 无 cookie 直连受保护 API→401 与豁免矩阵

功能域：06-异常处理与接口限流

## 用户目标

未携带任何身份标识直接调用受保护接口时，服务端一律拒绝且不产生副作用：旧的、伪造的身份写法同样被拒绝；登录注册接口自身的报错不触发会话失效的登出闭环。

## 前置条件

- 无身份标识的 HTTP 调用端；服务可用。

## 操作步骤

1. 不带身份标识直连故事生成、语音合成、播放进度保存、会话保存四个受保护接口。
2. 用错误凭证直连登录接口。
3. 不带身份标识直连身份查询接口。
4. 分别携带旧式访客标记、伪造签名与明文访客 ID 形态的身份标识调用受保护接口。

## 验收标准

- 步骤 1 全部返回未授权（401）。
- 步骤 2 返回登录错误，而不是会话失效语义（不触发前端登出闭环）。
- 步骤 4 的旧式、伪造与明文形态一律返回 401（不被接受），只有有效签名身份放行。
- 登录注册类调用不产生意外的身份清理。
- 本矩阵的 401 不导致已有登录态被误登出（有登录态的旁路上下文不受影响）。

## 边界与异常

- 与《路由守卫与重定向安全》拼成完整鉴权矩阵：页面层走网关中间件，本场景走接口层守卫。
- 登录注册接口报错不触发登出闭环，见《注册登录校验失败提示》；会话失效闭环见《会话失效后统一登出闭环》。

## 实现参考

- `lib/trpc/init.ts`（无有效身份时返回未授权「请先登录或以访客身份访问」）
- `lib/session.ts`（签名访客身份解析：无签名、伪造与明文一律视为无效）
- `lib/trpc/client.ts`（只有非登录注册类的 401 进入会话守卫）
- `lib/client/sessionGuard.ts`（访客与匿名 401 不走登出闭环）
