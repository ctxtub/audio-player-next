# 面向产品旅程的轻量测试方案

状态：已采用

## 目标

把开发精力放回用户旅程和 UI 实际表达，减少测试基础设施、重复断言和过期规则对迭代的阻塞。

## 决策

- 云端 CI 只做 lint、类型检查和生产构建，不运行重测试或浏览器模拟。
- 开发阶段按风险运行局部验证，不要求全量单元、集成或脚本测试。
- 用户视角浏览器验证只在交付最后阶段执行。
- 旧的用例映射、分层测试、源码字符串测试和内部测试入口退出当前体系并清退。
- 测试和文档直接使用功能描述，不再创建字母加数字的阶段号、用例号或任务号。

## 用户旅程验收

末期浏览器验证必须使用 production build、默认发布配置和页面可见入口。不得直接操作 Store、状态机、内部函数，不得注入测试状态或覆盖功能开关。

验证结论回答三个问题：用户能否完成目标、页面是否清楚表达当前状态、跨页面和音频行为是否连续。内部函数或测试入口返回正确不构成产品通过。

## 保留测试的范围

只保留少量高损失风险验证，以及真正从 UI 完成用户目标的末期浏览器旅程。测试资产不设数量目标；过期、重复或阻碍已确认产品调整的用例直接删除。
