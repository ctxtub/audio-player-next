## 用例规格

- 前置条件/夹具：`{{E2E_USER_A}}` 已有账号数据；浏览器同时持有活跃访客 cookie（含访客数据）。
- 步骤：1) 访客态停留 `/chat`；2) `/auth` 登录 A；3) 读取 UI 四块数据；4) AUT-API 确认访客行未被登录路径迁移/删除。
- UI 断言：登录成功后仅显示 A 的账号数据；访客期独有内容（如访客草稿消息）**不得**出现在登录态。
- 音频/浏览器断言：登录跃迁触发 `resetAccountData` 后浮窗/播放态清空重建，无旧账号音频残留。
- 网络/数据断言：核心断言——登录不触发迁移（迁移仅注册路径）；`Guest*` 行原样保留；`SESSION` cookie 签发且 `guest` cookie 保留（供后续登出回访客）；profile 读取以 user 主体。
- 清理：登出；清 cookie。
- 证据要求：`db.txt`（登录前后 Guest 表不变）、`network.json`（Set-Cookie）。
- 溯源：`lib/trpc/routers/auth.ts:105-133`（`:120` 登录 `setAuthCookie`，无迁移步骤）；`stores/accountSync.ts:105-121`（`:116-118` `isLogin` 上升沿→`resetAccountData` 重同步）；`middleware.ts:43-52`（有效会话优先续签）。
