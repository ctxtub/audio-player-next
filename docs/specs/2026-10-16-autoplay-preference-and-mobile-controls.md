# 自动播放偏好与手机播放体验

本次按用户明确要求调整首篇自动起播规则，取代此前“关闭连续创作仍自动朗读首篇”的行为。

## 自动播放

- “自动播放与连续创作”同时控制新故事集首篇自动起播和后续自动创作、接力播放。
- 关闭时生成的首篇只保存，用户点击播放后才出声；刷新仍保持关闭，手动播放不受影响。
- 生成、保存或语音准备期间关闭开关，取消尚未执行的自动起播。关闭后重新开启，不补播已经取消的请求。
- 开关开启后新建故事集仍正常自动起播、连续创作。已经开始播放的故事仍由播放按钮控制，关闭开关阻止后续自动行为。
- 自动请求取消不得显示语音失败，也不能影响手动播放、队列回听或其他作品会话。

## 手机端

- 故事集成员、创作集名、待播故事和展开播放器里的故事标题允许换行，不用单行省略隐藏主要内容。
- 正文标题使用紧凑字号；简介默认折叠并移到正文之后，重命名、删除收进“管理故事”，优先让正文进入首屏。
- 展开播放器保留半屏形态。底部固定显示“播放”“倍速与定时”“选集与记录”，点击即可看到对应操作，不需在长页面中寻找。
- 导航只改变播放器局部视图，不重建播放会话或暂停声音；桌面布局继续同时展示控制和选集。
- 在 375/430 像素及 375×667 短屏检查长标题、正文首屏、入口可见性、无横向溢出与可点击区域。

## 验证

复用现有创作与集合播放浏览器旅程，使用隔离 production build 和本地模拟上游。验证关闭后的首篇静默、手动播放、刷新保留偏好、开启后自动播放，以及生成中关闭不会迟到起播。补充手机布局与固定操作入口检查。运行静态检查、类型检查、生产构建和 diff 检查。
