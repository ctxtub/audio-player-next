## 缺陷记录 H-21

- 现象：在创作页完成一次创作后，去播放器页选择历史记录（"重新创作"）或生成历史（"回放"），当前创作**不被清空**；选提示词历史还会**追加新消息并推送新历史条目**。
- 根因：两条选中链都丢了"先清空当前创作上下文"——
  - 链 A：`HistoryPanel.handleSelectPrompt`（`app/(main)/player/components/HistoryPanel/index.tsx:43-46`）仅 `setPendingAutoSend＋router.push('/chat')`，`ChatLayout` 消费副作用直接 `handleSubmit`，`user.submit`（`stores/chatStore.ts:424-449`）纯追加；完成时 `record()` 再插一条历史。
  - 链 B：`replayGeneration`（`app/services/storyFlow.ts:142-158`）只覆盖 `playbackProgress` 源，不碰 `chatStore`/`generationStore`。
- 历史包袱：`90ff624` 曾调 `resetStoryFlow()` 清空；`8958a9d` 以防误删会话为由移除；段落化后连 `generationStore.reset()` 也丢失。"选中即切换"语义无人重新安放。
- 附带伤害：旧上下文全量进 Agent（串台）；`existingStories` 非空致新故事**不自动播**（`chatFlow.ts:126-129` 仅首次自动播）。
- 产品语义待决：选中历史后应"完全清空"还是"保留可返回"，由翔哥拍板后再修（修前勿动）。

## 用例规格

- 前置条件/夹具：`{{GUEST_SINGLE_STORY}}`（/chat 已有 1 个完整故事）；mock LLM/TTS。
- 步骤：1) /chat 确认 1 故事卡；2) 进 /player 切"提示词历史"点"重新创作"；3) 回 /chat 等自动发送完成；4) 另起：/player 切"生成历史"点"回放"。
- UI 断言：步骤 3 完成后旧卡不可见、新卡恰一；生成历史计数语义正确（旧上下文未复用）。
- 音频/浏览器断言：新故事自动播放（`existingStories` 门控下 bug 态必不播——天然 oracle）；回放播所选条目、播完即止零续写。
- 网络/数据断言：`agent.interact` 上下文不含旧故事文本；`chat.messages` 增量符合清空语义。
- L2 回归（`tests/test-history-select-clears-session.ts`）：seed 2 条旧创作→链 B replay 断 `chat.length==0 && phase==idle`；链 A select 语义断新会话恰 2 条且旧 id 消失；record 不复用旧上下文。
- 清理：清空会话。
- 证据要求：`ui-history-select.png`、`network.json`、`db.txt`。
- 溯源：见上根因行号；关联 `E2E-02-02`（同旁路不同失效模式）、`E2E-03-10/03-11`（/chat 原位回放，不可借 verdict）。
