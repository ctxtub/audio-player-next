## 用例规格

- 前置条件/夹具：AUT-NODE `createCaller` 直连 `auth.register`；调用侧包装注入
  （R4 改写：`MOCK_FAIL_MIGRATE_STEP=1` 为保留位，上游 Mock 无实现且 caller 走应用进程内代码、
  不经过 mock——改在同一进程内对迁移第二步首个 user 侧写点做一次性抛错包装，抛后即恢复；
  未改业务代码。实证见 `E2E-05-02/report.md` §1）。
- 步骤：1) 新访客造数（`config.updateMine` + `chat.saveConversation` 各一行，使半复制可观测）；
  2) 带注入注册同一用户名 → 抛 `INTERNAL_SERVER_ERROR`；3) 读取 `User` 表与 user 侧探针；
  4) 解除注入后重试同一用户名成功（经页内 fetch 走同一后端代码路径）。
- UI 断言：不适用（AUT-NODE；失败提示面由 E2E-05-10 覆盖）。
- 音频/浏览器断言：不适用。
- 网络/数据断言：核心断言——失败后 `User` 表**无**该用户名残留（回滚删除孤儿用户，`auth.ts:88-96`）；访客数据未被部分迁移（无半复制态）；重试可成功。
- 清理：页内 `auth.logout`；账号与访客行保留登记（不手写库删行）。
- 证据要求：`db.txt`（失败后 User 表查询为空）、caller 错误记录。
- 溯源：`lib/trpc/routers/auth.ts:88-96`（迁移失败→回滚删除孤儿用户）；`lib/trpc/routers/auth.ts:74-76`（三步事务边界）。
- 备注：服务端回滚为已核对语义；UI 面失败提示由 E2E-05-10 覆盖。
