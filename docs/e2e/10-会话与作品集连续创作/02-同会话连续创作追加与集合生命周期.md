# 同会话连续创作追加与集合生命周期

功能域：10-会话与作品集连续创作

## 用户目标

用户在同一会话里反复创作时，新的作品持续追加进同一作品集，顺序稳定；用户可以对作品集整体改名、收藏、移入回收站、恢复与永久删除，集合状态与成员作品状态保持一致。

## 范围与边界声明

本场景覆盖 T1「Conversation / Collection 数据底座」的追加与集合 CRUD（L1 + L2 隔离库严格断言）。
**明确排除**：T2 创作页面编排与强重置、T3 音频资产与进度、T4 Library UI 与契约迁移。

## 契约验收标准

### 1. 连续追加（append membership）
- 同会话第 2…n 次 promotion 复用同一集合，`position` 从 `max+1` 连续递增。
- 并发首作（同会话两个 promotion 同时到达）最终只能产生一个集合，且两件作品 position 互异（唯一冲突重试后仍成立）。
- 跨会话不互相追加，`workCount` 只统计本集合成员。

### 2. 列表与视图（list & views）
- `list` 支持 `view ∈ {active, favorites, trash}`：active 只返回 `deletedAt == null`；favorites 额外要求 `favoritedAt != null`；trash 只返回 `deletedAt != null`。
- keyset 游标分页：`limit + 1` 探测，`nextCursor` 只在确有下页时非空；游标与 `view`/`query` 绑定，篡改或不匹配 → `BAD_REQUEST`；严禁 OFFSET。
- 搜索命中集合标题或成员 Work 的 title/prompt/excerpt 时，**以 Collection 为返回单位去重**（同一集合多个成员命中只返回一次），且不扫描 `storyText`。

### 3. 详情（get detail）
- 只返回归属当前主体且 `deletedAt == null` 的集合；跨主体或已删除统一 `NOT_FOUND`（fail closed）。
- 成员按 `position ASC, id ASC`，附带音频投影（缺省 `missing`）。

### 4. 改名与收藏（rename & favorite）
- `rename` 先规范化标题（去空白、截断至 80 字符），空标题 → `BAD_REQUEST`；成功后 `titleSource = 'user'`。
- `setFavorite` 设置或清空 `favoritedAt`；仅作用于当前主体未删除集合。

### 5. 软删除 / 恢复 / 永久删除（trash lifecycle）
- `softDelete`：集合与其**全部成员 Work** 同时置 `deletedAt`（幂等；已删除再调返回成功）。
- `restore`：清空集合与成员 Work 的 `deletedAt`；对 active 集合调用 → `CONFLICT`。
- `deleteForever`：仅允许对回收站中的集合执行（否则 `CONFLICT`）；必须通过统一音频感知物理删除 seam 级联删除成员 Work（含音频 tombstone outbox 与进度），最后删除集合行；跨主体 → `NOT_FOUND`。

### 6. 主体对称与隔离（subject symmetry）
- User 与 Guest 在追加、分页、详情、改名、收藏、软删、恢复、永久删除上语义完全一致，分别落到 `StoryCollection` / `GuestStoryCollection`。
- 任意跨主体 id 访问都不得泄露或改动对方数据。
