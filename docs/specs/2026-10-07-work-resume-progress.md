# 切换作品后的毫秒进度保存

用户从作品 A 切到 B，再返回 A 时，新的播放会话应继续保存 A 的毫秒进度。已有进度行的旧 sessionId 不得使当前合法会话一直无法保存。

保存进度在同一数据库事务中校验当前 Subject 的 Anchor、作品和请求 sessionId；只有当前 Anchor 所属会话能够保存。允许该会话把旧进度行重新绑定到当前 sessionId；更新仍以读取到的进度行 sessionId 做条件写，避免覆盖并发变化。旧会话、切走后迟到的请求以及重播前请求仍必须无副作用。位置钳制、节流、完成历史与进度读取保持原契约。

工程验证使用独立临时 SQLite，覆盖用户/访客 A→B→A、新会话保存、旧会话拒绝、restart 归零和迟包保护。执行静态检查与隔离 production build，独立复核后提交。浏览器及线上运行验收继续由用户负责。
