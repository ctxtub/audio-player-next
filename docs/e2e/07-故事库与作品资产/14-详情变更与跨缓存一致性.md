# E2E-07-14 / M3-07: StoryWork 详情变更与跨缓存一致性规范

## 1. 规范概述
本规范定义了故事作品详情页（`/library/[id]`）在客户端执行变更操作（Rename、Favorite、Move to Trash）时的行为契约、状态流转与跨缓存一致性原则。

## 2. 核心架构约束与设计准则

### 2.1 变更范围与能力剪裁
- **仅支持三类变更**：
  1. `Rename`（重命名标题）：inline/对话框编辑，即时生效；
  2. `Favorite`（收藏切换）：与列表卡片复用同一套变更引擎与乐观缓存策略；
  3. `Move to Trash`（移入回收站）：无二次确认直接发起，成功后离开详情页并激活共享 Undo 会话。
- **严禁包含 Restore 与 Permanent Delete**：
  - 回收站中的作品根据安全与反探测设计严禁进入详情页；
  - 详情页组件严格不实现、不暴露 Restore 与 Permanent Delete 按钮或逻辑。

### 2.2 跨缓存一致性 (Cross-Cache Coherence)
1. **Rename 跨缓存同步**：
   - 成功时：详情缓存更新为服务端返回的完整 `StoryWorkDetailDTO`；所有已加载的列表缓存（Active、Favorites、各搜索条件）仅就地更新同 ID 卡片的 `title` 与 `updatedAt`；
   - 保护无限列表元数据：严格保持所有分页的 `nextCursor`、`hasMore` 及 `pageParams` 不变，绝不本地猜测将未命中的重命名项追加/插入到其他搜索结果列表；
   - 集合成员资格裁决：settled 时失效所有列表缓存（`libraryKeys.lists()`）与详情缓存，由服务端 refetch 最终决定搜索 membership；
   - 局部逆向回滚：失败时通过 `MutationJournal` 仅回滚当前作品在各列表与详情缓存中的标题，绝不全量覆盖快照。
2. **Favorite 一致性**：
   - 严格复用 M3-05 的同一套 `mutateToggleFavorite` 变更引擎，禁止在详情侧重复实现乐观策略；
   - 组件层严格不直接调用底层 `libraryClient.setFavorite()`，必须走 Query/Mutation 适配层。
3. **Move to Trash 与路由/Undo 联动**：
   - 发起移入回收站时无确认弹窗，立即走共享 M3-05 mutation 引擎；
   - Pending / 失败态：留在当前详情路由（`/library/[id]`），失败时触发局部逆向回滚恢复详情与列表缓存；
   - 成功态：立即从缓存中清除详情缓存（`removeQueries(detail(id))`），严禁对已移入 Trash 的作品再次发起 detail invalidation / refetch（避免无谓 404 错误与阻塞页面跳转），随后失效列表并导航离开跳转至 `/library`；
   - 跨路由 Undo 会话：由于 `LibraryUndoProvider` 挂载在 `/library` 与 `/library/[id]` 共享的 `layout.tsx`，离开详情跳回列表后 Undo 提示栏持续存在；
   - 真实 Undo 恢复：点击撤销后严格等待 `movePromise` 完成再调用 `restore` 并失效集合；恢复成功后**不自动重新导航打开原详情页**，用户停留在列表视图。

### 2.3 静态守卫与架构隔离
- 详情侧组件（`StoryDetail.tsx`、`app/(main)/library/[id]/index.tsx`）严禁直接导入底层 Client Facade（`@/lib/client/library`）、服务端内部实现（`@/lib/server/*`）或 Prisma 数据层；
- 严禁引入任何全局持久化客户端 Store（如 `libraryStore`）。

## 3. 回归测试用例矩阵 (Regression Test Matrix)
- **Regression 1**: Detail Rename 后 detail + active/favorites 已加载卡片标题一致，opaque pagination metadata 绝对不变，失败局部回滚；
- **Regression 2**: Detail Favorite 与 List Favorite 使用同一 mutation policy（不产生第二套 cache 规则）；
- **Regression 3**: Detail Move pending/失败时仍留在详情且数据 rollback；
- **Regression 4**: Move 成功后详情 route 离开、detail cache 不继续展示旧 active work；
- **Regression 5**: 离开 Detail 后 Undo 仍存在并能 restore；
- **Regression 6**: Undo 成功只 invalidate collection，不自动导航回原 Detail；
- **Regression 7**: Detail component/mutation adapter 不直接 import `@/lib/client/library`、`@/lib/server`、`@prisma`（组件层守卫）。
