# 配置乐观保存失败回滚

功能域：云端存储与多端数据调和

## 用户目标

访客在设置页修改播放偏好后，即使本次保存因网络或服务端原因失败，也能立刻看到自己的修改生效，并收到明确的失败提示；刷新后页面回到服务端实际保存的值，不出现"一半新、一半旧"的配置。

## 前置条件

- 访客首次打开站点，尚未保存过个人配置（全新身份）。
- 已进入设置页（`/setting`）。

## 操作步骤

1. 在设置页修改播放时长、首选语音、浮窗开关中的一项或多项。
2. 观察页面给出的保存结果提示。
3. 硬刷新浏览器，重新读取设置页显示的配置。
4. 对照服务端实际保存的配置，确认其仍为修改前的值。

## 验收标准

- 保存失败时，界面仍显示用户刚改的新值（乐观保留，不闪回旧值）。
- 保存失败时，页面给出明确的失败提示（toast 或等价提示）。
- 硬刷新后，设置页显示服务端保存的旧值（与失败前一致）。
- 连续修改只触发一次保存请求（防抖合并）。
- 服务端配置保持修改前的值；不出现部分字段已更新、部分字段未更新的不一致状态。

## 边界与异常

- 保存失败期间，界面显示的值与服务端保存的值存在分歧是预期行为；该分歧持续到下次刷新，刷新后以服务端值为准。
- 本场景覆盖"保存面"；"首次加载配置失败时的错误屏与重试"见《配置初始化门控与错误屏重试》。
