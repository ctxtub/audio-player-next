# 聊天历史切换当前创作

功能域：02-交互并发与竞态防御

> 文件名说明：本文件历史命名沿用旧入口名（旧 E2E-02-11），链接保持不变以避免重编号；
> 自 M4-07 起 History ownership 已回迁 Chat，`/player` 不再拥有任何 History 入口与实现，
> 本文件描述的是当前实现（Chat-owned History Surface），不是迁移前状态。

## 用户目标

在聊天页从历史记录里选一条旧创作，当前聊天切换过去继续听或继续写，被切掉的旧创作不再干扰新内容。

## 前置条件

- 聊天页已有 1 个完整故事（先完成一次故事生成，确认有 1 个 Modern Artifact 与 1 条提示词历史）。

## e2e-02-11-01

### 操作步骤（提示词历史 → Draft Session 干净重创作）

1. 在聊天页确认已有 1 个完整故事。
2. 点击 Composer 左侧「历史」入口打开 Chat History Surface，切换到"提示词历史"，选择一条并点"用此提示词重新创作"。
3. 面板关闭，同页自动发送完成（发送前先重置故事链路，旧会话清空；`pendingAutoSend → resetStoryFlow → beginChatStream → autoplayDraftStory`），观察旧内容是否可见、新故事有几个、Mini 是否可见。
4. 再次打开「历史」，确认旧提示词仍在历史中可返回；重载后确认不断点续播。

### 验收标准（M9-F01 冻结：正式 Draft Session 语义，旧 Transport-only 语义已退役）

- 点击「用此提示词重新创作」后恰好一次新 Agent 请求，且该请求上下文不含旧 assistant conversation。
- 新生成 Draft 建立正式 Playback Session：`source.kind='draft'` 且 `source.messageId` 为本次新 assistant 消息，新 `sessionId`，`status` 非 idle，`continuationMode='finite'`；真 server Anchor 身份为 `draft/该 messageId`。
- 首次实际 Transport 播放前 Session 已非 idle（全局 invariant：`Transport.play()` 时 `source !== null && status !== 'idle'`；同帧原子证据）。
- 实际 audio 自然起播（真实播放证据：自然 playing/ended/currentTime + loadedmetadata/readyState>=1），音源为 provider 合成产物（`blob:`/`data:audio/*`）。
- Mini 可见（`mini-now-playing`，`data-status='playing'`，只派生自 Session）。
- 旧 prompt/history 仍存在（提示词历史可见 + 隔离库：`GuestPromptHistory>=1` 且该提示词 `GuestGenerationHistory` 新增不覆盖旧条）。
- reload 后 Anchor 可 hydrate 为 ready（同一 `sessionId/source`）；不 autoplay；Transport 无旧 src（`hasAudioUrl=false/audioUrl=null`）且 DOM audio 无 src 且 `paused`。

## e2e-02-11-02

### 操作步骤（生成历史 → Work Session 有限回放）

1. 在聊天页打开「历史」，切换到"生成历史"，选择一条并点"回放此故事"。
2. 观察回放播放的是哪一条、Mini/Expanded 是否可达、播完后是否停止、有无触发续写。

### 验收标准（M9-F01 冻结：正式 Work Session 语义，旧 oneShot 语义已退役）

- 点击「回放此故事」建立正式 Work Session：`source.kind='work'` 且 `source.workId` 等于实际点击的 `record.id`。
- 该回放 Session 为 finite；不创建 Draft，不产生 `replay-text-*` identity。
- 实际 audio 自然起播（真实播放证据），音源为 M5/M8 provider 合成产物。
- Mini 可见；点 Mini 元数据可打开 Expanded（URL/会话不变，关闭后 Mini 恢复）。
- 不触发 Agent，不触发 AI continuation；不新增生成历史条目；不污染聊天消息。
- 回放结束后（`status='ended'`）仍是同一 Work identity（Session 与 Anchor 仍绑定最初点击的 Work）。

## 边界与异常

- History Surface 的归属与同页消费语义见《History UI Relocation / Chat-owned History Surface》（`docs/e2e/08-创作Artifact/07-HistoryUIRelocation.md`）；发送中选择排队、exactly-once 消费见该场景 M4-07-05～07。
- 聊天页原位回放的行为见《历史恢复卡回放重合成》《旧卡回放不消费新预载》。
- 生成中提交的互斥行为见《流式生成中再次提交互斥》。
- Modern Artifact 的 ready 只表示 StoryWork 已创建（Library handoff），不表示 audio ready；回放经 M9-F01 起统一走正式 Work Session（`PlaybackSessionFlow.playWorkFromHistory(record.id)`）。

## 历史结论（H-21 已修复，非待确认）

- 原现象（2026-09-10 前）：在创作页完成一次创作后，去旧 History 入口（当时位于 `/player`）选提示词历史"重新创作"或生成历史"回放"，当前创作不被清空；选提示词历史还会追加新消息并新增历史条目。
- 原根因：两条选中链都缺少"先清空当前创作上下文"。链 A：旧 History 面板选中提示词后直接跳转聊天页自动发送，追加写入且完成时再记一条历史。链 B：故事回放只覆盖播放进度来源，不触及聊天与生成状态。
- 修复（方案A，已合入）：ChatLayout 消费 `pendingAutoSend` 前调 `resetStoryFlow()`（清空旧会话/播放/预载/生成态），再自动发送；双浏览器复现转 PASS（run=2026-09-10T01-43-27-744Z-28d858）。
- M4-07 起 History 入口与实现已从 `/player` 回迁 Chat（`app/(main)/chat/components/HistoryPanel`），`/player` 回归纯 playback/compatibility surface；旧跨页步骤统一收敛为本文件 e2e-02-11-01/02 的聊天页步骤。
