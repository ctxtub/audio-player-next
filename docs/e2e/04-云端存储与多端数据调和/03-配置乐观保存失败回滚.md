## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}`；mock 注入 `config.updateMine` 一次失败（`MOCK_FAIL_CONFIG_UPDATE=1`）。
- 步骤：1) `/setting` 修改播放时长/首选语音/浮窗开关；2) 观察保存提示；3) 硬刷新后读取配置；4) DB 读取 `GuestConfig`。
- UI 断言：失败后 UI 仍显示新值（乐观保留）；刷新后回到服务端旧值；失败时有 toast 或等价提示。
- 音频/浏览器断言：不适用。
- 网络/数据断言：核心断言——`updateMine` 失败请求恰一次（防抖合并后）；DB 行保持旧值；无部分写入（字段级不一致）。
- 清理：恢复 mock；清 cookie。
- 证据要求：`ui-config-optimistic.png`、`network.json`、`db.txt`。
- 溯源：`stores/configStore.ts:201-213`（保存失败保留乐观值，catch 不回滚）；`stores/configStore.ts:284-303`（初始化门控联动 E2E-01-05）。**待验证假设 H-14**：失败后乐观值与服务端值长期分歧，直至下次刷新。
- 备注：与 E2E-01-05（初始化失败错误屏）互补：本例验证「保存面」，E2E-01-05 验证「初始化面」。
