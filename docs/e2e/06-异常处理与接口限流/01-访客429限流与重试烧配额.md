## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}`；隔离库确认该访客无历史调用；`{{E2E_STORY_4P}}` 播放就绪。
- 步骤：1) AUT-API 以访客 cookie 连续调用 `agent.interact` ×11（窗口 1 分钟内）；2) 第 11 次观察 429；3) 同窗口内在 UI 触发故事生成与临段预载；4) 观察共同失败与失败标记增殖（被拒尝试不计入配额、不延长窗口，见「限流语义」）。
- UI 断言：429 后流式终止有失败标记/重试按钮（非无限 sending）；toast 提示不重复轰炸。
- 音频/浏览器断言：预载耗尽重试后最终失败时，段落衔接停止且浮窗不残留「生成中」僵尸态（联动 E2E-03-11 预载面）。
- 网络/数据断言：核心断言——第 11 次调用返回 `TOO_MANY_REQUESTS`；限流窗口内的后续被拒尝试不再写入时间戳、不延长窗口（见「限流语义」），重试链（scan 证据：≤3 次、5s 间隔；`retryCount` 递增）与人工操作表现为共同失败与失败标记增殖，而非继续消耗配额；已保存进度不受 429 污染。
- 清理：清 cookie；删该访客行；等待窗口翻转或重建上下文。
- 证据要求：`network.json`（11 连调计数）、`ui-429.png`、`console.json`。
- 溯源：`lib/trpc/routers/agent.ts:17-19`（`guestLimit:10, authedLimit:30`）；`lib/server/rateLimit.ts:159-205`（`enforceProcedureRateLimit`，窗口默认 60s）；`stores/preloadStore.ts:29,109-126,163`（失败→`retryCount+1` 重试链）。**待验证假设 H-17（机制修正后）**：预载重试链与人工操作在同一窗口内共同失败、失败标记增殖（被拒不计数，见「限流语义」）。
- 备注：重试常量（3 次/5s）来自 scan 留档，行级出处以运行时 console 证据核定。

## 限流语义（与 `lib/server/rateLimit.ts` 实际行为一致）

- 被拒不计数：`checkAndConsume` 在 `timestamps.length >= limit` 时直接返回 `allowed: false`，不执行 `timestamps.push(now)`（`lib/server/rateLimit.ts:71-80`），429 被拒尝试不写入时间戳。
- 窗口不延长：被拒尝试不新增时间戳，故窗口 oldest 不后移、`resetMs` 不被推迟；窗口仅随成功写入的时间戳自然滑动，失败尝试不延长窗口。
- 成功才写时间戳：仅 `allowed: true` 路径追加当前时间戳并返回剩余配额。
- 历史表述「重试烧配额 / 继续消耗配额 / 互相挤兑→级联失败」已废弃，统一修正为「共同失败 + 失败标记增殖」。
