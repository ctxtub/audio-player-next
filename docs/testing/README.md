# 测试与交付验证

测试服务于产品交付，不建立独立的编号、层级、覆盖率或测试资产规模目标。

## 开发阶段

- 优先完成完整用户旅程和真实 UI 表达。
- 运行 `yarn test:fast`，并按改动风险做必要的局部检查。
- 不要求为每个需求增加单元测试、集成测试或浏览器脚本。
- 不使用读取源码字符串的测试来断言文案、样式、import 或文件结构。
- 不在生产代码中加入内部测试入口、测试专用状态入口或测试专用业务分支。

## 云端 CI

CI 只运行以下轻量工程检查：

```bash
yarn lint
yarn tsc --noEmit --incremental false
yarn build
```

CI 不运行数据库集成测试、全量测试套件或真实用户浏览器模拟。云端结果只证明代码能够通过静态工程检查和生产构建，不代表产品体验已经验收。

## 交付最后阶段

只有准备交付时才运行用户视角浏览器验证：

- 使用 production build 和默认发布配置。
- 从页面可见入口操作，不直接调用 Store、状态机或内部函数。
- 不覆盖功能开关，不注入虚构的播放、生成或缓存状态。
- 场景以用户目标命名，例如“新建创作后旧内容和播放状态被清空”，不使用字母数字代号。
- 一个用户目标对应一条完整旅程，避免拆成大量局部脚本。

末期浏览器入口：

```bash
yarn test:delivery-journeys
```

该命令在隔离的 production harness 中用 Chromium 从可见 UI 完整执行四条用户旅程。
只有发现明确 WebKit 兼容风险时，才用同一配置显式补跑受影响旅程的 WebKit project。

## 命名规则

禁止新增阶段编号、用例编号、任务编号或历史别名。文档标题、文件名、测试标题和代码注释都直接说明功能或风险。数据库错误码、协议标准、公开 API 名称等外部固有标识不在此限。
