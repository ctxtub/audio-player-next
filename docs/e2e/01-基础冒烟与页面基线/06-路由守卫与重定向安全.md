# 路由守卫与重定向安全

功能域：01-基础冒烟与页面基线

## 用户目标

没身份的人打不开受保护页面会被请到登录页，访客和登录用户各走各的门；登录页上的回跳参数只能跳站内，永远跳不到站外去。

## 子场景 A：匿名与访客路由守卫及开放重定向安全

### 用户目标

未登录用户访问聊天、播放器、设置页时被带到登录页并记住原目标；进入访客态后这些页面畅通无阻；登录页上的站外回跳参数会被截断，严禁跳往站外。

### 前置条件

- 访客首次打开站点（无既有身份）的干净会话。
- 服务可用，访客进入接口正常。

### 操作步骤

1. 在无身份状态下直接访问受保护页面 `/chat`、`/player`、`/setting`。
2. 访问 `/auth` 并点击「访客进入」，访客进入接口返回成功后获得访客身份。
3. 以访客身份访问 `/chat`、`/player`、`/setting`。
4. 携带站外回跳参数访问登录页（如 `/auth?from=//evil.com`、`/auth?from=https://evil.com`），点击访客进入并观察最终落点。

### 验收标准

- 未登录访问受保护路径时，被重定向至登录页并记住原目标（`/auth?from=<原路径>`）。
- 访客态可畅通访问 `/chat`、`/player`、`/setting`，无异常弹窗，控制台无未捕获异常。
- 访客进入接口调用成功，服务端建好该访客的配置记录；浏览器始终保持在本域。
- 站外回跳参数被归一化截断：最终只落在站内（默认 `/chat`），严禁跳往站外域。

## 子场景 B：已登录用户路由守卫、登录页反向拦截与站内回跳

### 用户目标

已登录用户直达各受保护页面不被打扰；误闯登录页会被弹回；带着合法站内回跳参数走完登录流程后，能回到原本想去的那一页。

### 前置条件

- 已注册账号 A，且处于已登录态。
- 服务可用。

### 操作步骤

1. 以已登录态直接访问 `/chat`、`/player`、`/setting`。
2. 以已登录态主动访问 `/auth`。
3. 带着合法站内回跳参数走登录流程（如 `from` 指向设置页），观察登录成功后的落点。

### 验收标准

- 已登录态直达 `/chat`、`/player`、`/setting`，无多余重定向。
- 已登录态访问 `/auth` 被反向弹回 `/chat`。
- 携带合法站内 `from` 参数走完登录流程后，回到参数指定的站内路径（如 `/setting`）。
- 守卫协作正常：控制台无未捕获的鉴权异常，不误清登录态。

## 边界与异常

- 未携带身份直接调用受保护接口时返回未授权，豁免矩阵见《无 cookie 直连受保护 API→401 与豁免矩阵》。
- 非法的站外回跳参数回落到站内默认页，不报错、不跳站外。
- 静态资源不受路由守卫影响。
- 注册与访客转正流程见《访客→注册三步迁移与数据保真》。
