# 旧数据回填与迁移守恒

功能域：10-会话与作品集连续创作

## 用户目标

升级到新版数据底座时，历史聊天快照与历史作品被安全、可重复地纳入 Conversation / Collection 结构：旧作品默认各自成集，只有存在可靠来源证据（`sourceMessageId` 命中同一主体且已归属某会话的 ChatMessage）时才合并进该会话的作品集；反复执行回填不产生重复数据、不丢数据、不产生孤儿。

## 范围与边界声明

本场景覆盖 T1「Conversation / Collection 数据底座」的 expand → backfill 阶段（L2 隔离库 + 证据脚本严格断言）。
**明确排除**：T2 连续创作编排、T3 音频资产、T4 Library UI；旧表在本阶段**不收缩、不物理删除**，仅做归属补全，保留回退读能力。

## 契约验收标准

### 1. 确定性 id 与幂等（deterministic & idempotent）
- 回填使用的会话 / 集合 id 由稳定业务键经 sha256 → UUID v5 形态派生；同一输入恒得同一 id。
- 集合另有 `conversationId UNIQUE` 约束；重复执行回填时，集合数、会话数、作品归属均不得变化（第二次执行为空操作）。
- 回填只处理 `collectionId IS NULL` 或 `position IS NULL` 的作品，绝不重排已归属作品。

### 2. 合并仅凭可靠证据（evidence-only merge）
- 仅当旧作品 `sourceMessageId` 命中同主体 `ChatMessage`（且该消息已归属某 Conversation）时，才把该作品并入该会话的唯一集合。
- 无可靠证据（无 `sourceMessageId` 或聊天记录已被替换）时，一律「一 Work 一 Collection」，**严禁按时间邻近猜测合并**。

### 3. 归属补全与 position（attachment & position）
- 旧 Chat 快照迁移进每主体一个 legacy Conversation（确定性 id），消息按原顺序重新分配会话内 position。
- 被合并进同一集合的多个作品按 `createdAt ASC, id ASC` 稳定分配 `position`，无重复、无空洞。
- 每件回填后的作品必须 `collectionId != null` 且 `position != null`。

### 4. 迁移守恒证据（migration conservation evidence）
- 回填前后必须采集并持久化脱敏计数：会话数、集合数、作品总数、已归属作品数、孤儿数（`collectionId` 指向不存在集合）、无 position 数。
- 回填后孤儿数 == 0、无 position 数 == 0；作品总数前后守恒（不新增、不删除）。
- 证据写入 `.e2e-results/2026-09-15-story-collection-continuous-creation/T1/`，不含任何用户内容或连接串。

### 5. 注册迁移归属（registration migration ownership）
- 访客注册升级时，Guest Conversation / GuestStoryCollection 以确定性 id 迁移为 User 对应行，已迁移作品的 `collectionId`/`position` 被重映射，聊天消息的 `conversationId` 被重映射。
- 迁移可重复执行，不产生重复行；Guest 原行保留给 30 天 GC 清理。
