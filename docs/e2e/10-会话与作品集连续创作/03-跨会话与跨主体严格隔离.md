# 跨会话与跨主体严格隔离

功能域：10-会话与作品集连续创作

## 用户目标

不同创作会话、不同用户、不同访客、用户与访客之间的作品集与作品绝不发生任何串读或串写；换会话创作只影响新会话的集合，绝不把作品错误并入旧会话作品集。

## 范围与边界声明

本场景覆盖 T1「Conversation / Collection 数据底座」的隔离与守恒（L2 隔离库严格断言）。
**明确排除**：T2 连续创作编排、T3 音频资产、T4 Library UI。

## 契约验收标准

### 1. 跨会话隔离（cross-conversation isolation）
- 会话 A 的 promotion 只写入 A 的集合；随后会话 B 的 promotion 必须创建 B 自己的集合，`A.workCount` 保持不变。
- `conversationId` 与集合一对一：任何时刻同一会话的集合数 ≤ 1。
- 读取会话 A 详情时不得返回会话 B 的成员。

### 2. 跨主体隔离（cross-subject isolation）
- User A 与 User B、Guest A 与 Guest B、User 与 Guest 可以拥有相同 `conversationId` 形态值、相同 `sourceMessageId`、相同标题，彼此互不冲突、互不可见。
- 跨主体读取 / 改名 / 收藏 / 软删 / 恢复 / 永久删除目标 id 一律 `NOT_FOUND`，且不得在目标主体产生任何行变更。
- 数据物理隔离：用户写 `Conversation`/`StoryCollection`/`StoryWork`，访客写 `GuestConversation`/`GuestStoryCollection`/`GuestStoryWork`，不得跨表落库。

### 3. 会话归属与状态（ownership & state）
- 用不属于当前主体的 `conversationId` promotion → `NOT_FOUND`。
- 对已 `closed` 会话 promotion → `CONFLICT`，不得产生集合或作品。
- `createNew`：新建会话关闭旧 active 会话；`expectedOldId` 与当前 active 不一致 → `CONFLICT`（防并发覆盖）。

### 4. 守恒不变量（conservation invariants）
- 任意成功 promotion 后：新增 Work 数 == 新增集合数 + 追加成员数，不存在无集合的孤儿 Work（`collectionId IS NULL` 的新作品）。
- 软删除集合后：集合 `deletedAt != null` 且其成员 Work 全部 `deletedAt != null`，不残留「集合已删、成员仍 active」的不一致状态。
- 永久删除集合后：成员 Work 与其进度、音频元数据一并消失，且音频对象删除进入 tombstone outbox（不直接触碰对象存储）。
