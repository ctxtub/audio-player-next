## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}`；完成一次故事生成并进入播放（产生进度行）；记录播放前的 DB 快照行数。
- 步骤：1) 新消息投递（delivered）后 ≤1s 内关闭标签页（`page.close` 模拟快速退出）；2) 重开同 cookie 会话；3) 对比 DB 与 UI。
- UI 断言：重开后最后一条助手消息是否缺失（刻画丢失面）；若进度源消息缺失，浮窗不得残留「断点就绪」假态。
- 音频/浏览器断言：悬空进度被 `hydrateFromDTO` 丢弃时 `audio.paused=true`、浮窗不显示可播状态。
- 网络/数据断言：核心断言——DB 快照是否缺尾部消息（1s 防抖未 flush + `skip-while-sending`）；进度行 `sourceId` 指向的消息是否存在；级联清理是否发生（进度行删除或保留）。
- 清理：清进度行、清空会话、清 cookie。
- 证据要求：`db.txt`（退出前后行集 diff）、`ui-reopen-after-exit.png`。
- 溯源：`stores/chatStore.ts:188-206`（1s 防抖 + sending 跳过，无 beforeunload flush）；`stores/playbackProgressStore.ts:157-186`（源消息缺失时丢弃进度并清理）。**待验证假设 H-16**：快速退出静默丢失会话尾部并产生悬空进度级联。
- 备注：数据丢失面刻画，非必然缺陷；判定结论写入运行时报告。
