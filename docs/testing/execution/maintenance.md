# 测试资产维护规则

## 新增测试的判断

只有以下情况才考虑增加自动测试：

- 缺陷可能造成越权、数据损坏、错误扣减预算或不可逆迁移；
- 逻辑稳定、可独立验证，并且人工验证成本显著更高；
- 现有用户旅程无法表达该风险。

新增前优先合并或替换现有测试。UI 文案、布局、按钮存在性和文件组织不写源码字符串测试。

## 浏览器旅程

浏览器旅程只在交付最后阶段执行，必须通过真实 UI 完成用户目标。禁止使用生产测试入口、直接状态注入、状态机直调或测试专用功能开关。

## 命名与文档

- 使用“用户做什么、看到什么结果”的自然语言标题。
- 不使用阶段号、用例号、任务号、字母数字缩写或别名表。
- 不维护测试数量、覆盖率分母、完成百分比或层级映射表。
- 过期测试直接删除，不保留会继续影响实现的兼容规则。

## 运行边界

- 测试不得访问生产端口、生产数据库、共享开发库或真实用户数据。
- 临时结果只写 ignored 目录，不提交截图、日志、cookie、token 或数据库快照。
- 失败必须按真实原因记录，不通过重试、放宽断言或跳过来制造通过。
