# 预载续写不污染聊天流

功能域：02-交互并发与竞态防御

## 用户目标

故事播放到段尾、系统在后台自动预载后续内容时，聊天界面保持干净：预载不伪装成用户消息出现，输入框里的草稿也不受影响。

## 前置条件

- 访客首次打开站点（无既有身份）。
- 先完成一次故事生成，正在播放由聊天卡片发起的故事，且播放临近段尾。

## 操作步骤

1. 播放故事，等待播放进度临近段尾。
2. 在临近段尾前，在输入框预置一句话，但不发送。
3. 等待后台预载续写触发。
4. 观察聊天流是否多出消息、输入框草稿是否还在、段落衔接播放是否正常。

## 验收标准

- 聊天流中不出现预载触发的"请继续故事"类用户气泡；预期不发生预载以正常用户消息身份进入聊天流。
- 预载的生成请求仍正常发生，段落衔接正常播放（段落衔接行为见《旧卡回放不消费新预载》）。
- 预载不新增生成历史记录。
- 若预载触发了会话保存，保存内容不把"请继续故事"持久化。

## 边界与异常

- 预载是后台行为：用户在界面上感知不到它，只感知到段落衔接不断流。
- 输入框草稿的保留行为见《自动续写期间输入框草稿保留》。
