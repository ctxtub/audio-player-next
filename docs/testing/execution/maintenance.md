# 测试资产维护规范与变更规则（MAINTENANCE.md）

本文档定义本仓库测试资产的维护规范、用例演化标准与质量审计门禁。所有协作者与自动化助手均须严格遵守。
数量、身份与调度口径唯一以机器权威为准；本文不维护任何手工总数。

---

## 1. 规范驱动开发（SDD）双向联动

1. **规范优先与同步更新**：
   - 凡涉及页面渲染、用户交互、API Schema 变更、鉴权守卫或状态机调整的代码修改，均须在对应的 `docs/e2e/` 场景下同步更新或新增用例规范。
   - 严禁在业务代码改动后留下失效或不一致的用例规范。
   - 严禁在用例规范未完成同步更新与核验前声称任务完成。

2. **单一事实来源（SSOT）**：
   - `docs/e2e/` 下的规范文件为系统行为断言的权威依据。
   - 实现代码若与用例规格产生分歧，须以产品契约与用例规格为基准进行对齐与澄清。

---

## 2. 身份与编号准则（catalog 驱动）

1. **唯一身份**：case 唯一身份为 kebab-case `case_id`（见 `tests/test-catalog.yaml`）；
   旧 `E2E-XX-YY` 编号已退役，仅 `legacy_aliases` 保留作回查，不得作主编号使用，不得新增旧编号。
2. **单用例规范要素完备性**：
   每份用例规范文件必须具备以下完整要素：
   - **元数据表格**：`case_id`、所属旅程（`journey_id`）、规范层级、优先级（P0/P1/P2/P3）、生命周期（`lifecycle_status`）、执行绑定（`executable_ids`）。
   - **用例规格**：
     - 前置条件与数据夹具（使用统一符号标识符如 `{{GUEST_FRESH}}`、`{{E2E_PORT}}`）。
     - 清晰的操作步骤序列。
     - 逐层断言：UI 断言、音频/浏览器断言、网络/数据断言。
     - 用例级清理要求。
     - 证据要求（指定必须产出的证据文件名）。
     - 代码溯源（指向具体的源码路径与行号）。

3. **数量口径**：一切计数（父组/原子 case/声明自动化/已实现/缺口）唯一以 `yarn test:catalog`
  （`scripts/check-test-catalog.mjs`）输出为准；文档内禁手工总数，数字与 checker 不一致时以 checker 为准并阻断。

---

## 3. 执行环境隔离与私有边界

1. **环境与数据绝对隔离**：
   - 严禁触碰生产环境与生产数据库（Docker 生产路径 `/app/data/app.db`、生产端口 `38080`）。
   - 严禁使用共享开发库 `prisma/dev.db`。
   - 测试服务使用当次隔离端口与当次隔离库，外部上游统一指向当次常驻 mock；具体端口/指针/所有权见 [隔离执行](./isolation.md)。
2. **凭据安全脱敏**：
   - 真实凭据、密钥与测试密码严禁进入 Git 跟踪范围。
   - 规范文档与代码中统一使用符号占位符（如 `{{E2E_USER_A}}`、`{{E2E_PASS_A}}`、`{{E2E_SESSION_SECRET}}`）。
3. **运行产物私有化**：
   - 执行产生的所有截图、控制台日志、网络拦截记录、数据库快照及运行报告仅留存于本地 `.e2e-results/`。
   - 根目录 `.gitignore` 确保结果与运行时文件永不被提交入库。

---

## 4. 调度治理与终态准入

1. **catalog 驱动调度**：
   - 自动调度集合以 `tests/test-catalog.yaml` 的 `lifecycle_status` 与 `executable_ids` 为准；
     `MANUAL` case 不进入自动执行队列。
   - 固定同一目标 SHA 的只读调研与 review 可以并行，但不得修改文件、启动服务或清理进程；
     独立 worktree 只有在显式分配独立 runtime/results 根和所有权后才能并行执行。
2. **终态门禁与通过项保护**：
   - 用例执行完成必须输出确定性 verdict，并生成包含全部断言证据的报告与机读行。
   - 具备完整有效终态证据与通过判定的用例受准入保护，调度队列仅调度待执行或未决项。

---

## 5. 变更审计标准

在对测试规范与资产进行任何修改时，必须通过以下确定性审计门禁：

1. **规范完整性**：数量口径唯一以 `yarn test:catalog`（checker）输出为准，本文件不手维护第二份总数。
2. **链接有效性**：`docs/e2e/README.md` 中全部引用链接与锚点必须能够正确解析。
3. **命名规范性**：全量规范文件与属性严格遵循 kebab-case `case_id` 身份口径（`legacy_aliases` 仅回查）。
4. **工作区整洁性**：执行审计前后确认 Git 状态未受临时产物或私有结果污染。
