# 播放状态一致性与核心体验修正

基于 2026-10-16 浏览器体验中确认的问题，先修复播放状态，再收口首次创作、注册入口和移动阅读体验。

## 播放状态

- 当前选中的故事不等于正在播放。故事集成员、播放器选集与迷你播放器统一显示正在播放、已暂停、播放完成、正在准备语音或播放遇到问题。
- 仅播放态显示动态声波；暂停、结束和刷新恢复为暂停后不得继续显示正在播放。
- 集内选集以实际播放的 Work 为当前项；排队或准备中的下一篇不能冒充正在播放的故事。
- 已知的实时音频时长和位置优先用于当前故事；刷新后使用已保存位置，未知时长明确为未知，只有实际准备时才显示准备语音。
- 正文页的当前故事时长也优先使用播放会话的实际时长，避免与播放器或集合详情不一致。
- 音频准备完成后刷新可见故事与集合的音频信息，不需用户刷新页面。
- 集内播放按钮统一经过已有的播放意图入口。准备另一篇时点回当前篇也应作废旧请求，避免页面直接暂停/继续绕过请求顺序保护。

## 后续体验

- 自动播放开关的最新行为见 [自动播放偏好与手机播放体验](2026-10-16-autoplay-preference-and-mobile-controls.md)：关闭后首篇也不自动朗读。
- 访客的“去注册”直接打开注册表单，注册后仍返回原页面。
- 点击“开始体验”后保留精简的主题建议与输入提示；新建空故事集继续提供可操作的创作入口。
- 手机故事集成员的标题拥有独立空间，主要播放控制保持可见且易点；正文优先于冗长摘要，缩小标题以减少首屏占用。
- 手机播放器优先展示标题、进度和播放控制，将选集与内容导航保留为易发现的次级内容；所有操作在短屏上仍可滚动访问。
- 桌面列表和设置页为默认位置的悬浮播放器预留实际高度，避免覆盖页面操作；创作页保留输入坞的布局。
- 用户可见称呼采用“故事伙伴”等自然表述，不展示 Agent 实现名称。

## 验证

开发阶段进行类型与静态检查；交付阶段使用独立数据库、本地模拟上游及生产构建，从可见 UI 验证播放→暂停→继续→结束→刷新→切篇，检查各界面状态一致与音频信息更新。复用现有集合播放旅程补充这些断言，并检查注册入口、主题建议和 375/430 像素移动布局。

真实 AI 内容、音色、线上时延和移动设备后台播放不包含在模拟服务验证结论中。
