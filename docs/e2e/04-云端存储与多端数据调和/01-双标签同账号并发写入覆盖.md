## 用例规格

- 前置条件/夹具：`{{E2E_USER_A}}` 登录态；同身份双浏览器上下文（标签 T1/T2）各挂同一会话；mock 放慢流。
- 步骤：1) T1 发送消息 A（完成）；2) T2 发送消息 B（完成）；3) T1 再刷新读取；4) 对比两标签与服务端 `chat.saveConversation` 快照。
- UI 断言：刻画 T1 刷新后是否丢失 T2 的消息 B（last-writer-wins 全量替换语义下预期被覆盖；若 UI 出现合并，登记为实际行为）。
- 音频/浏览器断言：不适用。
- 网络/数据断言：核心断言——DB `ChatMessage` 与最后一次 `saveConversation` 快照一致；T2 的消息 B 在 T1 保存后是否仍存在（全量替换 `deleteMany`+重建 vs 增量）；两标签交替发送 3 轮后无重复行、无孤儿 sending 行。
- 清理：清空会话；登出；清 cookie。
- 证据要求：`db.txt`（每轮快照行集）、`network.json`。
- 溯源：`lib/server/chatConversation.ts:63-88`（`:67` deleteMany、`:70/:87` `$transaction` 全量替换事务）；`stores/chatStore.ts:188-206`（保存调度）。**待验证假设 H-15**：双标签并发写时后写者整体覆盖、无增量合并。
- 备注：与 E2E-04-09（访客上限）共用「多轮写入后行集比对」手法。
