# 桌面悬浮偏好语义迁移（M6-01 Config Foundation）

功能域：云端存储与多端数据调和

## 用户目标

用户在设置页切换“桌面悬浮播放”后，偏好在刷新后保持；旧物理列数据无损迁移为新语义（false=宽屏 docked，而非隐藏入口）。

## 前置条件

- 已存在旧物理列 `floatingPlayerEnabled` 数据的行（或全新主体走默认）。
- 客户端读写新字段 `desktopFloatingPlayerEnabled`。

## 操作步骤

1. 读取配置 DTO，确认只暴露 `desktopFloatingPlayerEnabled`（无 legacy 字段）。
2. 全新主体首次读取，确认为 `true`（默认）。
3. 置 `false` 后重读（模拟刷新），确认为 `false` 且持久化。
4. 置回 `true` 后重读，确认为 `true`。
5. 旧物理列 `false` 的行，读取为 `desktopFloatingPlayerEnabled=false`（语义=wide-docked）。
6. Legacy PATCH `{ floatingPlayerEnabled: false }` 映射成功；新旧同时不同值 PATCH 拒绝（BAD_REQUEST）。

## 验收标准

- DTO 只含 `desktopFloatingPlayerEnabled`，不含 `floatingPlayerEnabled`。
- 默认 `true`。
- `true↔false` 可持久化，刷新保持。
- configStore 不同时保存两份字段（单字段收敛）。
- 物理列未 rename（Prisma `@map("floatingPlayerEnabled")`，无数据 migration）。
- 冲突 PATCH（新旧不同值）返回 BAD_REQUEST。

## 边界与异常

- 新旧同时相同值：以新字段为准，成功。
- 仅旧字段：映射为新语义，成功。
- 物理列 rename 即阻断（schema guard）。
