## 用例规格

- 前置条件/夹具：`{{GUEST_FRESH}}`；AUT-NODE `createCaller` 直连 `chat.saveConversation` 快速写入 >100 条（或 UI 长会话造数）。
- 步骤：1) 造 120 条消息（含 storyCard 变体）；2) 读取 DB `GuestChatMessage` 行数；3) UI 刷新读取列表；4) 对第 1-20 条旧消息再次保存一次全量快照（模拟旧客户端回写）。
- UI 断言：刷新后 UI 可见消息与 DB 保留集一致（最近 100 条）；无渲染错乱。
- 音频/浏览器断言：不适用。
- 网络/数据断言：核心断言——DB 行数 =100（`cappedMessages` 截断）；旧客户端回写包含被截掉的消息时，仍以服务端上限裁剪为准；`User` 表无对应截断（用户侧不设 100 上限，对照验证）。
- 清理：清空会话、清 cookie。
- 证据要求：`db.txt`（行数与首尾行 id）、`network.json`。
- 溯源：`lib/server/chatConversation.ts:92,136-138`（`GUEST_CHAT_KEEP_LIMIT=100`、`cappedMessages` 截断）；`lib/server/chatConversation.ts:140-160`（访客全量替换事务）。
- 备注：上限行为为已核对的服务端确定逻辑，本例验证边界值（100/101）与回写路径。
